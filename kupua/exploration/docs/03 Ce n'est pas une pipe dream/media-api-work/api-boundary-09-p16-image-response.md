## 1. Deciding Answer and Decision Table

**Accept this bounded review with the named corrections and unresolved contracts below.** Reuse Grid's image model, response writer, Argo entities and existing visibility policy. Add bounded ordinary-operation bulk image reads; do not invent a second image JSON format or treat raw ES hits as already-authorized, already-normalized images. Reuse existing single-image GET for standalone detail rather than requiring D9 to replace it. Kupua needs a real shared response normalizer and caller-owned overlay publication, not another cast to `Image`.

This preserves arbitrary-position browsing among millions, stable position and traversal through the density continuum. Image delivery, enrichment and hydration must support that experience without redefining ordered coordinates. Accepted approximate landing/presentation and useful selection limits remain intact. No universal snapshot, durable session, index migration, Thrall hook, implementation or D3 readiness restart is proposed.

## 2. Material Original Findings

### F1. Canonical image creation is policy and delivery work, not a free envelope

**Source:** [ImageResponse](../../../../../media-api/app/lib/ImageResponse.scala#L58), lines 58-132, builds response data from the parsed `Image` plus response fields, signs source/optional PNG and sometimes thumbnail URLs, computes validity/downloadability/persistence/cost/syndication/aliases, wraps edits, adds index provenance and custom instructions/restrictions, then emits tier-dependent links and actions. [The response writer](../../../../../media-api/app/lib/ImageResponse.scala#L325), lines 325-390, wraps file metadata, usages, leases and collections and translates crops to exports. [ArgoHelpers](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/argo/ArgoHelpers.scala#L16), lines 16-42, distinguishes single entities from collections; collection `length` is emitted data size, not ES total. [EmbeddedEntity](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/argo/model/EmbeddedEntity.scala#L11) and [EntityResponse](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/argo/model/EntityResponse.scala#L11) carry data, URI, links and actions separately and omit optional empty lists through their writers.

[ImageExtras](../../../../../media-api/app/lib/ImageExtras.scala#L44), lines 44-90, separates validity from downloadability: missing credit/description are non-overridable image checks, not download checks. Invalid reasons report invalid conditions even when an override makes the image valid. [CostCalculator](../../../../../media-api/app/lib/usagerights/CostCalculator.scala#L12), lines 12-52, considers restrictions, category, supplier exclusions and quota. [ImagePersistenceReasons](../../../../../media-api/app/lib/ImagePersistenceReasons.scala#L9), lines 9-136, includes edits, labels, collections, leases, usages and exports; it is not the deletion predicate. `Image.canBeDeleted` only checks exports/usages, then response actions apply permissions and tier. [Image](../../../../../common-lib/src/main/scala/com/gu/mediaservice/model/Image.scala#L34), lines 34-66; [actions](../../../../../media-api/app/lib/ImageResponse.scala#L160), lines 160-196.

The writer's cost calculation merges root rights with raw user overrides before wrapping, while other checks consume the parsed image. Do not silently replace this established behavior with client recomputation or assume it is equivalent to deriving every property from the final rights object. [Cost merge](../../../../../media-api/app/lib/ImageResponse.scala#L198), lines 198-211. [UsageQuota](../../../../../media-api/app/lib/UsageQuota.scala#L38), lines 38-43, synchronously awaits usage status with a default 100ms budget and converts failures to no exceeded quota before the feature-toggle check. This is source evidence of possible work, not a claim that every image waits 100ms or that every call makes a remote request; the usage-store implementation was not read. [S3 signing](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/aws/S3.scala#L75), lines 75-104, constructs a presigned GET; credential-provider internals were not accessed.

**Consequence:** reuse the canonical semantics and existing policy authorities. A count, key stream or rank response does not need image enrichment; an image-returning response does. Keep those costs separate without deleting image fields/workflows.

### F2. Lean projection requires two representations and a scoped parser

**Source:** [D3 lean resolver](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L727), lines 727-746 and 847-856, selects schema-derived image fields minus embedding/originalMetadata/fileMetadata, adding configured alias paths. It removes those top-level dropped fields from a copy before validation and retains the original projected JSON for aliases. [SourceWrapper](../../../../../media-api/app/lib/elasticsearch/SourceWrapper.scala#L6) carries both representations plus index and response fields. [Image's reader](../../../../../common-lib/src/main/scala/com/gu/mediaservice/model/Image.scala#L81), lines 81-132, defaults absent file/original metadata and several legacy fields, but requires identity, upload information fields, source and metadata as specified by the reader. [FileMetadata's reader](../../../../../common-lib/src/main/scala/com/gu/mediaservice/model/FileMetadata.scala#L55), lines 55-66, requires iptc/exif/exifSub/xmp maps when that object exists. A partial alias-only object therefore is not interchangeable with a complete `FileMetadata` object.

[Alias extraction](../../../../../media-api/app/lib/ImageResponse.scala#L411), lines 411-431, walks the original JSON, keeps actual JSON values and supplies false for absent existence aliases. Booleans are demonstrated in [alias assertions](../../../../../media-api/test/lib/ImageResponseTest.scala#L95), lines 95-174. Both [Kupua Image](../../../../src/types/image.ts#L205) and [API ImageData](../../../../src/dal/grid-api/types.ts#L403) nevertheless type aliases as string-valued. Prefer preserving JSON value meaning and converting only for display/search where needed, not coercing false into a truthy display string at the transport boundary.

The lean projection is not universally equivalent to full GET: absent original metadata defaults to an empty model, embedding becomes absent/empty, and expanded file metadata can only describe that defaulted model. `ImageExtras` also examines original byline for one advisory reason ([source](../../../../../media-api/app/lib/ImageExtras.scala#L59)). This is a source-level projection qualification, not a newly reproduced failure or a demand to restore the entire heavy payload. New lean readers need an explicit required-field decision; full GET must retain its existing contract.

[Kupua's source include list](../../../../src/dal/es-config.ts#L71), lines 71-127, includes labels, dimensions/orientation, several raw file-metadata leaves, rights, complete usages/leases and collection dates. [Field accessors](../../../../src/lib/field-registry.tsx#L969), lines 969-990, prefer server aliases and fall back to raw paths. Configured alias coverage of every consumed raw leaf was not established here. Keep this as a finite projection/configuration join, not a broad model audit. Preserve complete relationship arrays for maximum-date cursor synthesis; this report does not newly verify the sort extractor or its assertions.

**Consequence:** extract a shared lean parser/projection for D9, keeping ordinary `mapImageFrom` and existing GET behavior separate. Do not synthesize replacement image JSON or claim any field lost by projection is harmless because the remaining document validates.

### F3. Kupua normalization is incomplete; overlays do not repair nested baseline shape

**Source:** [D3 mapper](../../../../src/dal/grid-api-search-adapter.ts#L31), lines 31-48, unwraps usages, leases and collections but spreads all other fields unchanged. [EditsResponse](../../../../../common-lib/src/main/scala/com/gu/mediaservice/model/Edits.scala#L57), lines 57-106, nests archived/labels/metadata/rights/photoshoot inside `userMetadata.data`, and labels are individually embedded. [The flat Image contract](../../../../src/types/image.ts#L179), lines 179-191, expects flat archived/labels/metadata/etc. [The actual labels accessor](../../../../src/lib/field-registry.tsx#L792), lines 792-807, directly reads and joins `img.userMetadata.labels`. Thus a canonical D3 entity is not normalized for that accessor merely by the current cast. This is a source-established shape mismatch, not a browser reproduction.

The new shared normalizer should unwrap all those fields, optional expanded `fileMetadata.data`, usages, leases and collections; retain metadata, identity, upload/soft-delete data, assets and complete relationship fields; and separately preserve wrapper actions/needed links. Do not manufacture defaults for missing required asset dimensions/MIME merely because Kupua types require them: [Asset](../../../../../common-lib/src/main/scala/com/gu/mediaservice/model/Asset.scala#L10), lines 10-14 and 61-82, permits absent size/MIME/dimensions. Existing view fallbacks and the accepted legacy-data surface need compatibility assertions before changing the internal type.

[Enrichment extraction](../../../../src/dal/grid-api-search-adapter.ts#L59), lines 59-79 and 178-198, already returns an optional per-ID map without mutating the store. [deriveImage](../../../../src/lib/derive-enriched-image.ts#L90), lines 90-123, computes local baseline values and gives overlay cost/validity/reasons/rights/persistence/actions/syndication/usages precedence where present; it does not flatten edits or file metadata. [Enrichment store](../../../../src/stores/enrichment-store.ts#L62), lines 62-79, supports replacement and ID upsert, not automatic lifetime/cancellation policy. An old overlay can remain until its owner replaces it; global cache freshness is not proven here.

[The existing detail adapter](../../../../src/dal/grid-api/grid-api-adapter.ts#L49), lines 49-103, unwraps only top-level `data` and returns `ImageData`; [mergeReconciledFields](../../../../src/dal/grid-api/argo.ts#L81) is an identity function. It is neither the required flat normalizer nor an `ImageDataSource`. Its unwrap loses top-level actions/links unless the caller retains them first. Both singleton and collection wrappers carry actions in current Scala; a type comment saying actions are not on GET's data must not be read as saying the GET envelope lacks actions.

**Consequence:** one common normalizer plus result-carried overlay/delivery metadata, with publication remaining in the caller. Existing pure unwrap/link helpers are reusable components, not a completed normalization layer.

### F4. Detail and selection need different successful-absence handling from failed reads

**Source:** [Standalone detail](../../../../src/components/ImageDetail.tsx#L238), lines 238-273, uses resident results first, otherwise `dataSource.getById`, with a local cancellation guard before setting standalone state. [DAL single/bulk contracts](../../../../src/dal/types.ts#L279) and [bulk contract](../../../../src/dal/types.ts#L494), lines 494-505, return images without overlays. [Strangler](../../../../src/dal/strangler-adapter.ts#L27), lines 27-38, delegates both ID methods to ES. [Direct singleton](../../../../src/dal/es-adapter.ts#L730), lines 730-733, wraps bulk; [direct bulk](../../../../src/dal/es-adapter.ts#L2198), lines 2198-2244, runs 1,000-ID chunks concurrently, filters found documents, and turns aborted chunks into empty arrays. Comments equating all-parallel work with one round-trip latency are not measurements.

[Selection's constructor](../../../../src/stores/selection-store.ts#L344), lines 344-358, directly constructs ES. [ensureMetadata/hydrate](../../../../src/stores/selection-store.ts#L538), lines 538-650, populate an ID-keyed cache and increment publication revisions. `ensureMetadata` tolerates failure as absent metadata; `hydrate` returns on thrown failure but, on success, removes omitted IDs, repairs anchor ownership and may notify once. It captures selected IDs before awaiting. These are the specific owners to change; this partial read does not certify all late-result guards, panel lifecycle or range behavior.

**Recommendation/inference:** return normalized images and overlay maps together from the DAL image-read path and publish them at the guarded cache/detail commit. Keep false/empty server values authoritative, preserve membership on read failure, and let successful missing/hidden omissions drive existing hydration repair. Do not turn transport failure, cancellation, an errored multi-get item or incomplete batch into a successful empty set. The existing optional-enrichment null contract remains valid for supplemental data but cannot stand in for primary-read completeness. The existing Grid adapter throws on several auth/server failures; its comments and the development absence directive are not proof of one already-uniform contract.

### F6. Raw hits, validated images and emitted entities have different cardinality

**Source:** [Lean resolution and result assembly](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L737), lines 737-746 and 858-895, drops `JsError` results with `flatMap`, unzips surviving image/tuple pairs, reverses both together, and sets `nextSortValues` from the surviving tuples. Total comes from ES only when requested, otherwise zero. It is not the emitted count. Parsing/writing may also throw; those failures are not successful omissions. [D3 controller](../../../../../media-api/app/controllers/MediaApi.scala#L853), lines 853-912, maps resolved hits through the shared helper; that helper checks permissions but does not itself call `isVisibleToAccessor`. Existing search filtering supplies policy scope elsewhere; this report does not claim D3 currently leaks hidden images or audit that query policy.

New bulk reads must check each found image's visibility. A future ordered window that drops hits due to validation or visibility must not report a short enriched page as end-of-stream, or silently compact positions while retaining raw ranks/totals. Even the current `nextSortValues` is survivor-based, not an explicit raw-scan completion signal. Kupua's mapper further skips missing entity data while passing `json.sortValues` unchanged ([source](../../../../src/dal/grid-api-search-adapter.ts#L180)); current server entities normally contain data, but future partial/link-only output must not break alignment.

**Recommendation/inference:** P17 must decide the smallest endpoint-local completion/progress contract, including behavior when every raw hit is omitted, bounded extra work and incomplete ES execution. Do not prescribe unbounded refill loops or filter hidden IDs in the browser. Validation/visibility semantics must be compatible with total/rank/key-stream membership. This does not demand a shared universal snapshot or reopen all existing GET/D3 behavior.

E033 remains centrally qualified. [Report 04 F1](api-boundary-04-reconciled-recommendation.md#L25) and [R6](api-boundary-04-reconciled-recommendation.md#L226) record a synthetic short HTTP-200 timeout/failed-shard response returning the same non-null map as its complete control. Thrown-error/observed-abort handling is not execution-completeness validation.
