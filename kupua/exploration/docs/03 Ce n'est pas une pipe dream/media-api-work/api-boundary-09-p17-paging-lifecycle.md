## 2. Original-Source Material Findings

### F1. GET is reusable machinery, not a complete positional API

**Current source:** [ElasticSearchModel.scala](../../../../../media-api/app/lib/elasticsearch/ElasticSearchModel.scala#L319) parses URL parameters; omitted/invalid integers default, offset must be nonnegative, and length cannot exceed 200. There is no lower length check or offset-plus-length bound there. Length zero is usable for count-only ordinary GET. [ElasticSearch.scala](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L373) uses legacy sort selection, from/size, exact totals by default and ticker aggregations; suppressed totals become zero. Its `lookupIds` at line 166 is an internal pinned-ID search, not the route behind all GET IDs: [QueryBuilder.scala](../../../../../media-api/app/lib/elasticsearch/QueryBuilder.scala#L151) composes the ordinary IDs filter with other filters. No lookupIds route appears in the fully read [routes](../../../../../media-api/conf/routes).

The common client's index-creation setting is **101,000**, despite its nearby older 25,000 comment ([ElasticSearchClient.scala](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/elasticsearch/ElasticSearchClient.scala#L145)). This is creation-source evidence, not inspection of any deployed setting, and not a supported deep-offset API guarantee.

[MediaApi.scala](../../../../../media-api/app/controllers/MediaApi.scala#L800) creates next/previous links from offset and total; the helper adds `toDate` while the parameter reader reads `until`, and its serialization does not retain every search field. Do not promote the old plan's link-derived "snapshot" prose to a guarantee or undertake an unrelated link repair here. The examined real [Kahuna service](../../../../../kahuna/public/js/services/api/media-api.js#L41) issues GET through the search relation with explicit options. Its [range loader](../../../../../kahuna/public/js/search/results.js#L330) sets `countAll:false`; its [search helper](../../../../../kahuna/public/js/search/results.js#L539) supplies its own last-search date boundary and defaults counts on. This directly justifies preserving GET behavior while adding Kupua-local contracts; unknown consumers are not thereby covered.

### F2. D3 has the cursor mechanics; page totals and continuation have narrower meanings

**Current source:** body parsing in [ElasticSearchModel.scala](../../../../../media-api/app/lib/elasticsearch/ElasticSearchModel.scala#L91) admits scalar/null cursor values, tier from the principal, parsed default hiding, reverse/End and count intent. D3 rejects nonzero offsets, empty/duplicate/unresolved sorts and malformed tuple shapes; it reduces leading-null cursors to a missing-primary query, reverses physical sorts and returned arrays, and handles End missing placement ([ElasticSearch.scala](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L740)). These are useful building blocks, not a generic admitted sort language for new public operations.

With PIT, D3 searches no explicit index, uses the PIT target and renews for one minute with the search timeout applied. Without PIT, it calls `prepareSearch`. The response adopts nonempty refreshed PIT IDs or retains the requested ID. It deliberately removes implicit `_shard_doc`; public cursors survive PIT expiry and synthesis, with a unique semantic ID suffix required. Preserve this behavior. Reverse continuation is the first returned tuple at the backward frontier, **not** the convenience `nextSortValues`, which is the last canonical-order tuple. The client already uses per-hit tuples; its mapper does not consume that convenience field.

`countAll:false` explicitly returns **zero even with nonempty hits**. Count enabled means the effective query's count: ID-target lookup and null-zone filters can produce subset totals, not the retained browsing total or number of remaining images. The client [mapper](../../../../src/dal/grid-api-search-adapter.ts#L110) currently sets count intent from cursor absence, ignoring the DAL's explicit `trackTotalHits` hint; therefore cursorless End/target calls count too. New endpoints should label total scope/availability or adapt it explicitly; they must not replace the session total with zero/untracked/subset values. Existing D3 wire zero need not be changed to establish that client rule.

**Test-read:** the complete [ES assertion file](../../../../../media-api/test/lib/elasticsearch/ElasticSearchTest.scala#L747) includes GET/D3 deleted-intent/rights/date contracts, actual-ES fixture paging, reverse frontier, null-zone and End, PIT expiry classification, deliberate tiebreaker truncation, complete unique-ID walk and lean alias regression. These tests were read, not run. The base/fixtures install and purge data when executed; none was executed here. They do not establish ordinary-target handle admission, HTTP-200 partial execution refusal, every principal, or deployed capacity.

### F3. Preserve ordinary lifecycle, not migration-transparent sessions

**Current source:** [prepareSearch](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L689) selects completion-preview, running-migration or current routing and adds the migration dedup predicate when appropriate. The getter near line 105 separately prefers a migration copy then current. Those are shared behaviors to leave intact. D3's PIT branch intentionally bypasses them. A new ordinary endpoint should resolve its configured current target at admission, then let a PIT bind it; it should not accept arbitrary target names or turn a later migration-status lookup into frozen context. Uniqueness/single-target assumptions and maintenance behavior remain explicit deployment decisions during the unsupported migration case.

The direct [PIT lifecycle](../../../../src/dal/es-adapter.ts#L888) opens on configured ES index, returns the raw identifier and treats close failure as benign. The store [starts PIT open, PIT-less first page and ticker count concurrently](../../../../src/stores/search-store.ts#L2252), tolerates open failure and closes an opened context after a successfully resolved stale search. This is **not** one atomic snapshot across page one, later windows, map, rank and summaries. Preserving that accepted trade-off does not require a combined open-and-first-page route.

Refreshed-ID ownership is unfinished even though expiry guards exist. [Small-set fill](../../../../src/stores/search-store.ts#L1013) and [backward extension](../../../../src/stores/search-store.ts#L2672) clear explicit expiry but do not adopt non-null refreshed IDs. [Bidirectional loading](../../../../src/stores/search-store.ts#L1327) runs concurrent pages and prefers the forward refreshed result except when either recovery clears the PIT. The [expiry wrapper](../../../../src/stores/search-store.ts#L1416) prevents cleared contexts being resurrected. These are source facts; no claim is made that older IDs have actually failed in the deployment. The full [PIT tests](../../../../src/stores/search-store-pit.test.ts) cover mocked expiry races, open rejection, generation timing and stale-open cleanup, not a server-issued-handle implementation.

**Proposal:** keep short-lived ordinary contexts and reauthorize each request. New endpoint-issued handles should bind server-selected target, principal, purpose and expiry; bind map query/sort/phase scope where continuation depends on it. An integrity-protected stateless representation is a candidate, not a durable session requirement or an already implemented safety property. Do not invalidate sibling handles after every request: existing forward/backward overlap must remain possible. Return refreshed successors; a lost response may fall back to the last acknowledged context only within explicit bounded recovery, otherwise browse may resume live while map assembly must fail closed. ES acceptance of predecessor IDs, successor selection under overlap, authentication identity binding and multi-instance validation remain unproved contract details. No exactly-once close, replay prevention, revocation store or universal snapshot is promised. Accepted already-expired/closed contexts should close idempotently; malformed/foreign handles are refusals, not "expired" or permission to close an unrelated context.

### F4. E033 reconciliation applies differently to maps, ranges and rank

**Historical executed evidence:** [report 04 F1/R6](api-boundary-04-reconciled-recommendation.md#L24) records a complete control, timed-out short page and failed-shard short page, each returning the same non-null one-entry map. The full [synthetic fixture source](../../../experiments/api-boundary/api-boundary-04-e01.ts) has four mocked requests per case and intentionally asserts that result. This is a previously executed characterization, **not** an experiment rerun here, a real ES observation or browser-publication measurement.

**Current source independently read:** [map collection](../../../../src/dal/es-adapter.ts#L1986) opens its dedicated PIT, runs valued then missing-primary phases, tracks refreshed IDs, uses full internal cursor tuples and strips public tuples, and closes in `finally`. Thrown errors/observed aborts discard arrays. But it inspects **raw hit length, not timeout/shard flags**, when declaring exhaustion. [Map publication](../../../../src/stores/search-store.ts#L1269) accepts any returned non-null map after its abort check. Thus E033's amended wording is correct; there is no unconditional present-day complete-map guarantee. Map exactness means complete enumeration of its declared view, not membership equality with every other operation.

[Range collection](../../../../src/dal/es-adapter.ts#L2254) is a live, no-PIT, source-free walk with exclusive start/inclusive end, null-zone crossing and cap-plus-one lookahead. It may return partial IDs after cancellation with `truncated:false`; that flag denotes cap overflow, **not** execution completeness. Its paging helper also ignores HTTP-200 execution flags. This is a source-derived risk for ranges, not a claim that report 04 executed a range reproducer. [Rank](../../../../src/dal/es-adapter.ts#L1282) builds lexicographic predicates, including selected-maximum special dates and nested wrapping, then uses live `_count` without PIT. Exact mathematical predicates do not certify complete shard execution or simultaneous membership with a separate PIT.

**Necessary endpoint-local contract:** reject or explicitly mark incomplete execution before returning exact keys/rank/count or reporting exhaustion. Inspect the applicable search/count shard response; search timeout, failed shards or early termination when applicable cannot become exact completion. Transport success and `track_total_hits:true` alone are insufficient. For maps, every required phase must finish under its admitted view before publication; incomplete/expired attempts return absence, never a partial map. For ranges, distinguish bound reached, exhausted, cap-truncated, cancelled and execution-incomplete; cap plus one requires an actual extra in-range key, not merely another raw hit. Preserve successful live ranges and their useful cap. For approximate profiles, preserve explicit provenance instead of upgrading every presentation value to exactness.

These checks belong in new operations, not a global change to [ElasticSearchExecutions.scala](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/elasticsearch/ElasticSearchExecutions.scala#L12): that shared wrapper currently treats successful responses as success, while ordinary GET only logs timeouts. Changing it would affect unrelated searches, aggregates, usage queries and other services.

### F5. Raw hits, decoded images, authorized membership and visible items are different counts

**Current source:** [legacy resolution](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L703) drops invalid images; [lean resolution](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L727) strips heavy fields only for validation while retaining alias source. D3 builds hits **and tuples** only from successfully decoded images, so `nextSortValues` and emitted length are post-validation values; `total` remains ES-derived. The strip prevents the known partial-fileMetadata omission but does not make every indexed document valid. The [client mapper](../../../../src/dal/grid-api-search-adapter.ts#L178) can additionally skip null entity data while passing the tuple array through. Its typed cast is not a runtime alignment validator.

The controller's [shared image-entity helper](../../../../../media-api/app/controllers/MediaApi.scala#L853) computes permissions and calls the existing image writer; it does not itself filter result-list membership. The query path includes tier filters, while individual [image reads](../../../../../media-api/app/controllers/MediaApi.scala#L768) explicitly check visibility. New keys/count/rank admission must apply principal/query restrictions **before** ES selection/counting; post-hoc image omission cannot make leaked keys/counts safe or repair offsets.

**Proposal, not current behavior:** key pages use raw source-free identities/tuples, complete execution and an explicit scan frontier/exhaustion state. Image windows additionally need an omission policy and hit/tuple alignment. Do not infer corpus exhaustion from fewer decoded/visible images than requested, or silently compact omitted images and claim the same exact rank/map coordinates. The smallest safe initial exact-window policy is an explicit endpoint-local failure on a decode/alignment defect; any bounded skip/fill alternative must state raw progress, coordinate meaning and resource budget. Hidden/missing batch omissions can be legitimate, but decoding/item/request failure must not be reported as confirmed missing. Detailed image-response parity remains a coordinator join with original P16 evidence, not an endorsement of that draft.

### F6. Typed D3 expiry is narrower than direct fallback, and callers still matter

**Current source:** D3 emits `410` with `search-after-pit-expired` only for supplied-PIT missing-search-context failures; malformed PIT errors are not that contract ([ElasticSearch.scala](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L854), [MediaApi.scala](../../../../../media-api/app/controllers/MediaApi.scala#L900)). The [client classifier](../../../../src/dal/grid-api-search-adapter.ts#L154) preserves refusals, including authenticated/structured failures and retry indications, while narrowly classifying transport/bare gateway unavailability. [Strangler](../../../../src/dal/strangler-adapter.ts#L47) retries explicit expiry once through API without PIT and clears its returned ID; unavailable can fall back once to ES; offset bypass is separately explicit. Its complete tests assert these boundaries and cancellation. Direct ES instead has a broad message regex matching 400/404/410 ([source](../../../../src/dal/es-adapter.ts#L1042)); do not copy that into new API lifecycle handling.

The independently read [restore catch](../../../../src/stores/search-store.ts#L3967) treats any non-abort error as grounds for `seek(cachedOffset)`. A [shallow seek](../../../../src/stores/search-store.ts#L2927) then passes positive offset without PIT/cursor, which Strangler routes directly to ES. E017 remains a conditional source chain, not a live exploit. An API-only adapter must remove ES fallback **and** callers must not treat refusal as an instruction to start a different recovery operation.

E013's previously missing server premise is now supported: D3 explicitly supplies zero on untracked cursor pages; the [centred helper](../../../../src/stores/search-store.ts#L1393) passes the forward-page total, and [restore](../../../../src/stores/search-store.ts#L3919) tests that value for indexed-tier targeting while preserving `get().total`. E014 is separately retained: saved tuple supplies rank, refreshed tuple supplies neighbours. Neither conditional source mismatch has been reproduced in the UI here, and neither justifies stronger sessions.

Cancellation checks, request abort and generations suppress stale publication; they do **not** establish cancellation of Scala futures or ES tasks. `executeAndLog` offers a Future, not a request-disconnect cancellation hook. A 10-second per-search timeout (and the source comment about cluster timeout) is not an aggregate collector deadline, CPU quota or complete-result guarantee. New server work needs page/byte/tuple validation, bounded keep-alive, no-image key projection, admitted operation work and production concurrency policy. Do not silently serialize existing parallel browsing/hydration or lower useful limits to solve unspecified capacity concerns.

### F7. Authentication and admitted targets must remain local to the new contract

**Current source/test-read:** [Authentication.scala](../../../../../rest-lib/src/main/scala/com/gu/mediaservice/lib/auth/Authentication.scala#L47) routes provider outcomes and invokes the authenticated block; [ApiAccessor.scala](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/auth/ApiAccessor.scala#L29) allows ReadOnly only GET and Syndication only qualifying GET image paths. The full [controller assertions](../../../../../media-api/test/controllers/MediaApiTest.scala#L112) explicitly expect both machine tiers to be denied D3 POST without an ES call. This supports preserving the policy, not a claim that all real providers/principals were exercised. No credential/provider-storage path was followed.

D3's parsed positive deleted intent is scoped to the uploader before hits and totals when delete permission is absent; ordinary GET uses a narrower raw-string check ([MediaApi.scala](../../../../../media-api/app/controllers/MediaApi.scala#L586), [D3 admission](../../../../../media-api/app/controllers/MediaApi.scala#L876)). Consequently GET length zero is not an unconditional replacement for D7. Reuse the D3 admission semantics for new count/key/rank/image-window operations, then the shared filter builder and runtime-mapping requirements; do not rewrite GET in this packet. Principal/method coverage and ordinary-target integrity remain explicit release decisions, not permission to loosen shared auth or add migration machinery.
