### F2. Preserve AI Compatibility, Including Empty Membership and Health

**Source facts:** [Kupua](../../../../src/dal/es-adapter.ts#L1144) defaults/clamps weight to 1, skips embedding at zero, uses AND lexical matching, and for intermediate weights makes an unfiltered size-zero max-score probe followed by a boosted lexical/vector `should` query with the ordinary prefilter. It does not set `minimum_should_match`. The probe's null/zero maximum falls back to scaling 1; source does not prove the probe always produces a useful maximum. Preserve the implemented ranking unless separately changed, rather than certify the guide's quality claims. Results carry scores and synthetic index/ID tuples; they are not ordinary ES cursors.

[Grid controller](../../../../../media-api/app/controllers/MediaApi.scala#L677) defaults to 0.85, obtains a normalized-key cached embedding even before zero-weight dispatch, and separates ranking text/similar-image intent from parsed filters. [Grid execution](../../../../../media-api/app/lib/elasticsearch/ElasticSearch.scala#L210) uses OR lexical matching; intermediate weights run two searches, rescore semantic candidates lexically, resolve images, fill cosine scores, deduplicate and fuse. [HybridResult](../../../../../media-api/app/lib/elasticsearch/HybridResult.scala#L49) handles missing/mismatched/zero vectors using semantic minimum -1 and theoretical-min/max normalization. [VectorUtils](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/VectorUtils.scala#L13) establishes the actual fallback preconditions. Grid's count query returns the whole filter pool, not loaded-hit counts; filters-only and conflicting-ranking cases are separate existing contracts. Existing Grid AI must stay unchanged.

**Empty-AI scope defect:** [decorator](../../../../src/lib/ai-search-params.ts#L16) converts `[]` to `ids: ""`; [buildQuery](../../../../src/dal/es-adapter.ts#L492) adds an ID filter only for truthy IDs. Thus a zero-hit AI search publishes total zero but its ticker/facet/expanded queries can count the underlying CQL/filter pool, not zero AI members. Nonempty IDs remain additionally constrained by current filters/freeze, so even there counts are live intersections, not immutable properties of loaded images. The cache test covers nonempty sets and reorder only. **S8/S9 need an explicit empty-ID-set meaning, distinct from omitted ID restriction**, shared by client/API serialization; do not silently adopt Grid pool totals or replace the loaded total.

**Health/deployment:** [browser health](../../../../src/lib/bedrock-proxy-client.ts#L30) quietly returns false on failure; [startup](../../../../src/main.tsx#L20) probes once and [widget](../../../../src/components/AiSearchInput.tsx#L189) hides when unavailable. URL-provided `aiQuery` still reaches the store regardless of widget availability, including zero-weight lexical mode. The [development plugin](../../../../scripts/bedrock-embed-proxy.mjs#L104) actually invokes the model for health, caches availability, has no in-flight probe deduplication, and registers only `configureServer`. Its purported LRU normalizes keys but does not refresh insertion order on hits or coalesce simultaneous misses. Browser abort reaches embedding fetch, not the plugin's AWS send; a later embedding failure sets server availability false but does not automatically re-probe/update the already-mounted client. These are source facts, not live calls.

The server [Embedder](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/aws/Embedder.scala#L21)/[Bedrock](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/aws/Bedrock.scala#L41) use the same nominal Cohere V4/search-query/256-float shape; the development model can be overridden. ### F3. Ordinary Facet Guards Do Not Cover Expanded Results or Cached Presentation

[Ordinary fetch](../../../../src/stores/search-store.ts#L4006) cancels the prior debounce/request before cache lookup; it resolves superseded debounce promises and checks generation/signal after the complete static/dynamic response. Scope is recomputed after debounce; IDs are sorted to avoid refetching merely for AI reorder. Immediate bypasses only debounce; force also bypasses cache, circuit breaker and loading/error gates. Successful elapsed work can open a persistent circuit; only a successful subsequent forced fetch can close it. This is not a new query-specific automatic reset.

New search aborts aggregate work but **does not clear** old static/dynamic/expanded/named/usage data or the circuit. The UI does not check their cache key before rendering. A failed replacement or open circuit can therefore leave old-scope values beside a new query, and typeahead can read them. Retaining a previous presentation while loading may be intentional; presenting it as current-scope evidence is not established. Count fields missing from a successful aggregate response become zero in the [adapter](../../../../src/dal/es-adapter.ts#L851), and zero-count unselected options disappear in [facets](../../../../src/components/FacetFilters.tsx#L424). Quiet catches do not prove every absence stays distinguishable from successful zero.

[Expanded fetch](../../../../src/stores/search-store.ts#L4119) has one shared controller and per-field loading/cache state, but no post-await signal, request identity or scope check. Fetch already aborted after body parsing can still resolve because [ES transport](../../../../src/dal/es-adapter.ts#L648) yields before returning without checking again. A response can consequently repopulate expansions after search/base-fetch reset. Missing `result.fields[field]` leaves the loading flag set; an old catch can clear a newer same-field loading flag. Collapse removes data but is not an ownership token. Preserve independent expansion and isolated dynamic failures, but S8 needs scope-owned result/finalization and an explicit absent-field outcome across the actual transport.

[Ordinary assertions](../../../../src/stores/search-store.test.ts#L2580) prove immediate/circuit/cache behavior, trailing debounce, cancellation on cache hit despite an abort-ignoring producer, AI set-keying, loading gates, promise settlement, force and dynamic isolation. They do not test expanded publication interleavings. [UI assertion](../../../../e2e/local/ui-features.spec.ts#L601) records an immediate call and deliberately returns without fetching it; it proves intent routing, not fresh buckets or rendered counts. Use those existing homes for separately authorized affected-slice checks, not a new test framework.

### F4. Typeahead Cache, Deduplication and Remount Are Separate Contracts

Registered resolvers skip field-local cached data when their own filter exists, otherwise read buckets without a context fingerprint. Cold calls use current/live CQL with that field removed; dotted keys use parser-based removal, while static removal is regex-based. Static vocabulary survives count absence. `is:` deliberately mixes ticker, top-category-derived and named-filter counts, does not generally remove its own `is:` scope, and can give warm/cold differences: photo/illustration warm sums use only returned category buckets; cold named counts query those categories directly. [Collection resolver](../../../../src/lib/typeahead-fields.ts#L509) consumes ready tree IDs; P21's boot-time default-free counts are not its suggestion counts.

AI typeahead is not uniformly loaded-set-scoped: cold requests do not call the AI ID decorator, whereas warmed ordinary facet buckets and ticker counts may already be restricted to loaded IDs. The guide's simple 'world-scoped' description is therefore insufficient. S8/S9 must name warm/cold scope per suggestion/count source before claiming parity. Do not impose universal loaded-ID scope on exploratory typeahead without a UX decision.

[LazyTypeahead](../../../../src/lib/lazy-typeahead.ts#L154) aborts the previous pass and threads its own signal into registered/dynamic requests. It resolves all parsed fields with `Promise.all`; no request coalescing is implemented, so repeated fields/cold passes can issue separate requests. [Installed TypeaheadField](../../../../node_modules/@guardian/cql/src/lang/typeahead.ts#L47) simply delegates; there is no hidden cached promise. Abort is rethrown by [safe aggregation](../../../../src/lib/safe-aggregation.ts#L17); the cold `is:` catch suppresses errors internally but the outer superseded promise is already rejected. The plugin/popover focus/destroy guards in F1 narrow late-publication risk; no claim of visible options updating after destroyed-editor completion is made.

**Remount source defect:** [ensureRegistered](../../../../src/components/CqlSearchInput.tsx#L85) registers the custom-element class only once with the first `LazyTypeahead`. [Installed class](../../../../node_modules/@guardian/cql/src/cqlInput/CqlInput.ts#L36) closes over that argument and supplies it to each new plugin. Home/Clear remount wrapper children, but do not replace the registered class. The first wrapper's aggregate/ticker refs cease updating after unmount while its captured datasource remains bound. Live query can still update through the reused resolver's ref, so this is **not** a claim every query string freezes; the stale objects are cache callbacks/datasource ownership. A later datasource injection or remount can therefore use an old cached scope/owner. A full-page reload creates a new realm and is different. Characterize warm cache -> Home/Clear -> new search and datasource replacement in S8/S10 before wiring API-only ownership.

**Assertions read:** [resolver tests](../../../../src/lib/typeahead-fields.test.ts#L12) cover empty static-chip stripping, parser-based dynamic self-exclusion and absent dynamic data; [scheduler tests](../../../../src/lib/lazy-typeahead.test.ts#L22) cover live-AST ref ordering and superseded registered request rejection. They do not mount/register/remount the custom element or compare warm/cold AI count scopes. Parser reserved-value and configured-path semantics remain P23's exact join, not inferred from those tests.

Facet/status-bar query actions also call updateSearch without cancelling either pending editor timer. P19's 250ms table-header callback is a separately retained action clock, not repaired here.

The URL can retain the newer sort while the buffer/store use the earlier one. Controls do not disable sort during loading. This is a source-supported interleaving, not a performed UI reproduction. [Typing E2E](../../../../e2e/local/browser-history.spec.ts#L831) uses mocked Bedrock and an injected AI datasource. ### F6. Polling Adds the Same Cumulative Delta Repeatedly

[Poll](../../../../src/stores/search-store.ts#L717) never advances `newCountSince`; every tick queries arrivals since the same frozen boundary (or later explicit `since`). [Producer](../../../../src/dal/es-adapter.ts#L707) returns counts over exactly that query and has no per-poll deduplication. Yet ticker/subcounts are added to their previous accumulated values. With unchanged arrivals, two ticks add the same category increment twice, while `newCount` correctly remains the latest cumulative count. This closes P09/P13's precise unresolved producer/caller join. It is independent of accepted metadata/deletion drift or universal snapshots; immutable upload time does not make repeated overlapping windows disjoint.

Generation checks reject previous searches, not overlapping ticks within one search. There is no in-flight/same-generation response-order guard; visibility return can overlap an interval request. Failed ticks quietly retain prior counts, and ordinary startup `Promise.all` still waits for count completion despite parallel initiation. There is no count AbortSignal/deadline in the inspected client path. [StatusBar](../../../../src/components/StatusBar.tsx#L197) hides zero/equal-total category badges, displays supplier breakdowns and timestamp, and uses those values as filter affordances; repeated addition affects real UI, not only diagnostics. Counts/tickers feed `is:` suggestions and facets too.

**S7 consequence:** preserve fixed browse freeze, live new-image banner and separate first-page total ownership. Agree whether category updates are cumulative-since-baseline or disjoint deltas, then assert two identical polls, a changed poll, overlapping responses, failed count, previous-search response and refresh. Do not fix this by moving the browse freeze every poll or by silently adopting new snapshot semantics. The read store assertion blocks and P18's full test reading do not establish these cases; no new test was executed and no project-wide test-absence claim is made.

### F7. Overlay Publication Is Guarded, but Lifetime and Policy Consumption Differ

Every current store write was read. [Fresh ordinary](../../../../src/stores/search-store.ts#L2416) and [focus fallback](../../../../src/stores/search-store.ts#L1515) replace only when `result.enrichment` exists; an empty supplied Map clears old entries, undefined leaves them intact. [Successful focus-centred search](../../../../src/stores/search-store.ts#L1851) upserts even with a new-search fallback page; [fill](../../../../src/stores/search-store.ts#L1070), [extends](../../../../src/stores/search-store.ts#L2586), [seek](../../../../src/stores/search-store.ts#L3721) and [restore](../../../../src/stores/search-store.ts#L3931) also upsert after their guards. Target/backward/forward maps are combined explicitly. AI does not publish or clear enrichment, even if a future AI result carries it. Probes have no adapter side effect. S1 normalization remains correct within its accepted scope and does not alter this lifetime.

The [store](../../../../src/stores/enrichment-store.ts#L67) has no per-ID removal, eviction cap, scope/principal key or persistence. Upsert replaces an entire same-ID entry, not a field-wise merge, so omitted fields in a replacement fall back to baseline. Entries from evicted pages remain; upsert clones the entire accumulated Map. Hence buffer capacity does not bound overlay memory/copy work during long browsing. No measured slowdown is alleged. Conversely a replacement page can remove an overlay still used by retained off-buffer selection, reverting its display to local policy. In hybrid mode this matters today: [Strangler](../../../../src/dal/strangler-adapter.ts#L55) can return ES results without overlays for positive-offset or unavailable paths, and AI remains ES-backed. It is not evidence that an old server decision still applies to a refreshed same-ID baseline.

**Actual subscribers/precedence:** [hook](../../../../src/hooks/useEnrichedImage.ts#L26) selects by ID and memoizes image/overlay references; deletion/replacement changes that selection and recalculates, unrelated upsert retains the same entry reference. [deriveImage](../../../../src/lib/derive-enriched-image.ts#L92) always calculates baseline first, then nullish-overrides cost, valid, reasons, rights, syndication and usages; false and empty collections survive. `noRights` remains baseline-derived by explicit [test](../../../../src/lib/derive-enriched-image.test.ts#L196).
