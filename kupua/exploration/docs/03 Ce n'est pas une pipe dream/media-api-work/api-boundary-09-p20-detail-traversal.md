### F1. Ordered Traversal Is One Client Path Across Three Tiers

It does not consult the full position map. [Data-window](../../../../src/hooks/useDataWindow.ts#L329) separately uses total to choose indexed versus local view coordinates. Source defaults are at most 1,000 small, above 1,000 through 65,000 indexed, and larger/disabled-indexed seek; configuration provenance remains P23. ### F2. Settled Paths Do Not Establish Supersession of Pending Actions

These are source-supported preconditions, not reproduced UX failures or incidence estimates.

- **Pending traversal:** [pending resolution](../../../../src/hooks/useImageTraversal.ts#L189) stores direction only, reads the latest current image/callback when a window changes, and has no originating query/entry token. A new current ID/search while pending can redirect that intent if the current image and neighbour remain resolvable. A missing current ID clears pending; immediate reverse/resident navigation also clears it. Inactive preview passes null and clears pending/proactive eligibility; detail unmount destroys refs. The [single current unit test](../../../../src/hooks/useImageTraversal.test.ts#L85) proves the null-separated reopen case, not every same-mounted ID/query change or close/reopen batched without a committed null state. An empty/failed/cooldown-declined extend does not itself change results/origin, clear the pending direction, or schedule an independent retry.
- **Return frame:** [return centring](../../../../src/hooks/useReturnFromDetail.ts#L155) captures a row and virtualizer/custom callback before an uncancelled rAF. Close -> reopen before that frame can centre the now-hidden list using the previous close's row; later close of the unchanged new entry preserves that moved native position. Query/resize/origin/density changes have P19's exact geometry qualifications. A callback to an unmounted old virtualizer is not proof it moves the new view. The [unit rAF](../../../../src/hooks/useReturnFromDetail.test.ts#L86) is synchronous, so it cannot refute this interleaving.
- **Preview exit settlement:** [cleanup](../../../../src/components/FullscreenPreview.tsx#L196) schedules resize debounce/safety-cap/rAF work without a captured preview/entry token or unmount cancellation. The [registered target resolver](../../../../src/hooks/useScrollEffects.ts#L289) intentionally resolves current focus, current origin/tier and current geometry at execution, unlike detail's captured row. That avoids one stale-geometry problem but can centre newer focus after another action/reopen. Boolean `initiatedRef` makes ordinary duplicate exit finalization harmless; it is not a unique session identity. [Exit helper tests](../../../../src/lib/fullscreen-exit.test.ts#L5) cover rejection/native-state booleans, not old asynchronous exit completion versus a new preview session.
- **Other clocks:** retain P19's old indexed scroll-seek timer issuing a new current-generation seek, and density rAF's real unmount cleanup but missing same-mounted search ownership. Hidden list layout remains active behind detail, so those callbacks can affect the shared buffer/return path. A request generation cannot invalidate an action that has not issued its request yet. Do not equate prefetch's inactivity session, browser entry key, search identity, container generation and request signal.

**Smallest consequence:** affected client briefs need deterministic pending direction -> new context, close -> reopen before rAF, and preview exit -> newer focus/session assertions in existing homes. Preserve unchanged-entry placement and legitimate current-geometry resolution. No generic navigation framework, universal snapshot or automatic gesture rewrite is justified.

### F3. Touch, Zoom and Media Absence Have Distinct Current Contracts

[Detail swipe callbacks](../../../../src/components/ImageDetail.tsx#L336) and nav strips exist only for resident neighbours. At an unloaded edge, horizontal touch rubber-bands; it does not invoke the keyboard's pending fetch branch. Proactive extension normally supplies headroom, but initial edge entry or delayed/failed extend is a real boundary to preserve or explicitly disposition. FullscreenPreview has pinch/pan and clickable strips, **not** the detail carousel/dismiss hooks; do not promise identical touch affordances on these two surfaces.

[Carousel](../../../../src/hooks/useSwipeCarousel.ts#L165) chooses horizontal direction after 10px, commits on velocity/distance, copies incoming media before navigation, clears side panels, and cancels a committed WAAPI animation on effect cleanup; resize commits it immediately. [StableImg](../../../../src/components/StableImg.tsx#L40) does not actually skip the write merely because `data-committed` exists: it removes the flag, compares resolved URLs and allows thumbnail-to-full upgrade. Comments about universally shared decoded textures or always skipping writes are not current guarantees.

[Dismiss](../../../../src/hooks/useSwipeDismiss.ts#L208) uses downward velocity/distance, permits upward cancellation, and pre-centres only a traversed detail before revealing the list. Normal hero/fallback dismiss changes history immediately; fullscreen dismiss waits for a transition event before toggling native fullscreen. The fullscreen transition callback lacks the hero branch's timeout safety net and cleanup removes only touch listeners. Interrupted transitions remain a source-only lifecycle acceptance case, not proof of a currently observed empty image.

[Zoom](../../../../src/hooks/usePinchZoom.ts#L148) owns touch pinch/pan, click/double-tap, wheel, momentum, Space and keyboard pan/Home/End. Current toggle scale is 3 and max 5, despite older 2x/4x prose. Zoomed input suppresses traversal; horizontal wheel at 1x can navigate history. Caller image-change effects reset external scale/DOM styles, while the hook's internal scale/pan/momentum closure is keyed by refs/enabled, not image identity. A pending step resolving after zoom or external image change is not established safe merely by resetting `scaleRef`; preserve that precise interleaving in any future gesture-touching brief. No broad gesture refactor is requested by this packet or the unstarted hardening proposal.

Two concrete failure/absence boundaries matter for S6a/S10:

1. [Standalone fetch](../../../../src/components/ImageDetail.tsx#L245) has callback cancellation, but no caller AbortSignal and no ID-bound stored result. After standalone A succeeds, same-mounted absent B leaves A in `standaloneImage` while B is pending; B missing/rejecting only sets a failure flag, so A still wins `imageFromResults ?? standaloneImage` and bypasses the no-image branch. Old pixels/metadata can therefore be labelled by a different URL context; this is a source case, not a performed browser reproduction. The existing missing UI also calls transport failure 'does not exist in the index', stronger than nullable absence establishes. Reuse GET with ID-bound image/overlay publication and quiet absence, not selection membership mutation or extra bulk routing.
2. [Detail image error](../../../../src/components/ImageDetail.tsx#L820) compares absolute `target.src` with [relative thumbnail URLs](../../../../src/lib/image-urls.ts#L50). With `/s3/thumb/...`, another failed thumbnail still differs from the relative string, so the intended terminal text fallback is not reliably reached. [Preview rendering](../../../../src/components/FullscreenPreview.tsx#L473) has a no-URL placeholder but no onError fallback. New delivery acceptance must cover missing URL, failed full image, failed thumbnail, decode rejection and returning to a usable list, not merely a successful canonical JSON response. No actual network loop or browser rendering symptom was measured here.

### F4. Prefetch Is Media Work, Not Ordered-Data Publication

[Prefetch](../../../../src/lib/image-prefetch.ts#L244) uses resident neighbours only: default stable radius four ahead/one behind, fast radius immediate neighbours plus both far offsets, 280ms post-burst fill and 2s idle close. Desired-radius cancellation preserves the newly visible image; touch thumbnail loaders are untracked, and idle close lets in-flight work finish. The shared hook also runs an initial prefetch effect when a position becomes known. FullscreenPreview additionally calls prefetch on entry. Exact request count is not simply radius size and the in-flight map is not all browser media work.

The 30-entry loaded set and in-flight map are keyed by **image ID**, not resource URL/version. Touch decode marks the set and notifies listeners; desktop prefetch only warms HTTP cache. Completion handlers delete from the **current** session map by ID rather than from the captured session/loader; an older completion can remove tracking for a newer same-ID request. Closing detail/preview does not explicitly close this module session; the post-burst callback may still use the captured old result array. These affect resource tracking/cache freshness, not store image/tuple authority. Existing [fake-image tests](../../../../src/lib/image-prefetch.test.ts#L114) cover cadence/radius/visible-request protection, not real mobile decode, signed-URL expiry or cross-session same-ID completion.

[URL helpers](../../../../src/lib/image-urls.ts#L195) currently derive development proxy URLs from ID/config, with orientation, screen/DPR/native cap and AVIF defaults; zoom uses the current 2.5 multiplier, not its older 'doubles' comment. A successful decode of one URL is not proof a refreshed signed URL for that ID remains usable. P25 should join URL selection/expiry to centre, side panels, prefetch and zoom together. Retain existing presentation quality and bounded useful lookahead; no speculative prefetch optimization, background metadata fan-out, new proxy or performance concession follows.
