### F2. Hydration Success, Failure and Obsolete Membership Are Different

The complete [bulk producer](../../../../src/dal/es-adapter.ts#L2198) sends 1,000-ID chunks all at once with `Promise.all`. It filters on `found && _source != null`, matches through source IDs at the caller, and carries neither per-item failure nor logical completeness in the result type. Non-abort chunk errors reject the logical read; DOM AbortError becomes an empty chunk, and an already-aborted call returns `[]`. An ES item carrying an error instead of a found source is indistinguishable to this filter from omission. A fulfilled malformed/short logical response has no requested-ID accounting. These are source contracts, not a live failure reproduction.

Current selection callers pass **no AbortSignal**, so do not describe those callers as currently aborting hydration on navigation. For a proposed abort-aware bulk API, forwarding the producer's empty/partial-abort result as complete success would be destructive. A nullable outcome also requires caller changes: current `images.map`/iteration assumes an array. Do not introduce `null` only in transport and call the migration complete.

[Hydrate](../../../../src/stores/selection-store.ts#L591) captures `selectedIds` before awaiting, without a hydration/selection-session token. If at least one captured ID is omitted, it constructs `nextIds` from that captured Set, not current membership. Thus: hydrate `{A,B}` -> clear or select `{C}` -> successful result `{A}` can restore A and discard C, and can reset a newer anchor. If all captured IDs return, membership is not overwritten, but old cache entries/revisions and reconciliation can still publish. Concurrent mount hydration and `ensureMetadata` are not deduped against each other. The route is under [StrictMode](../../../../src/main.tsx#L68), with no hydrate cleanup/idempotence guard; effect replay can issue concurrent reads in development.

[EnsureMetadata](../../../../src/stores/selection-store.ts#L538) has a narrower, intentionally useful guarantee: pending IDs dedupe requests; cache completion never adds membership; after awaiting it consults **current** membership before scheduling reconciliation. `clear()` invalidates queued idle reconciliation but does not clear metadata, pending fetch IDs, abort network reads or invalidate hydration. Cache completion after clear is therefore not itself selection resurrection. Failed metadata reads settle through reconciliation over the currently cached subset, rather than holding every field pending forever. The nearby comment saying fields remain pending is not the full behavior.

**Tests read:** [store assertions](../../../../src/stores/selection-store.test.ts#L498) prove successful omission/anchor repair, failure with retained anchor tuple, cache revision semantics and cleared-idle-callback isolation. [Panel E2E](../../../../e2e/local/selections.spec.ts#L440) gates `ensureMetadata`, checks clear plus late success leaves zero selection, and checks rejected metadata leaves three selected while usages settle to the two resolved images. It does **not** run the captured-Set hydration interleaving above. [DAL tests](../../../../src/dal/selections-dal.test.ts#L85) explicitly expect empty-on-abort and missing omission; no item-error/incomplete-logical-read assertion was found in this complete file.

**Candidate consequence:** S6b needs one complete-success/absence contract across all chunks, with item/decode/request/cancellation failure not authorizing missing-ID repair, plus caller-owned publication guarded against obsolete selection sessions. Preserve legitimate current selected additions/removals and deliberate cache reuse; do not blindly use `generationCounter` as a request token because metadata and reconciliation also advance it. Keep hidden/missing omission indistinguishable through Grid visibility policy (P15/P16 evidence), not browser filtering. Do not add principal-sensitive overlays to an unguarded cache completion. This is a scoped implementation requirement to approve, not a current fix.

### F3. Range Retry, Lifetime and Limits Need Composed Assertions

1. **Unknown direction is not reliably retried.** The [hook](../../../../src/hooks/useRangeSelection.ts#L251) retries only when both `walked === 0` and IDs are empty. The [real producer](../../../../src/dal/es-adapter.ts#L2301) increments `walked` before checking overshoot. When an evicted later anchor is guessed as the start and ES returns any later hit, it can return `{ids:[], walked:1, truncated:false}`; the hook then adds only the clicked target instead of swapping. At actual exhaustion it can return zero and retry. The [mock](../../../../src/dal/mock-data-source.ts#L866) precomputes endpoint positions and returns zero for reversed endpoints, hiding this difference. The complete hook unit file tests only `resolveInBufferRange`; the real DAL overshoot test itself [expects walked 2 for one retained ID](../../../../src/dal/selections-dal.test.ts#L205). No automatic server-side endpoint resolution is justified; characterize and agree the client ordering/retry contract.
2. **A newer range supersedes a range; clear/search does not.** Generation/controller refs live in the route-level hook. No effect binds them to search key, selection clear, sort, Home, route departure or anchor epoch, and there is no unmount abort. An old successful add walk can repopulate cleared selection or mutate the new search's selection; an old remove walk can remove newly selected overlapping IDs. Same-search density/detail transitions need not cancel legitimate work. Source distinguishes these cases; no runtime incidence is claimed.
3. **Busy-state writes precede stale checks in catches.** A superseded rejecting walk can clear `isRangeWalking` while its successor is still pending. If a pending server walk is replaced by an in-buffer gesture, the fast path does not clear the old busy flag; the ES abort can resolve empty, and its obsolete success path returns before clearing it. The visible [busy dot](../../../../src/components/SearchBar.tsx#L35) consumes this state. Put completion/finalization under the same owner as membership, not just the success add/remove. Non-abort range failures currently emit an **error toast**; missing anchor emits a warning; cap emits a warning. The development absence directive is not evidence these paths already return quiet null.
4. **The cap is a walk cap, not a selection-size cap.** The producer returns at most 5,000 IDs only after one extra in-range probe, in 1,000-hit pages. The hook explicitly prepends target, which may be excluded at the lower bound or beyond the truncated prefix, and the existing anchor remains selected. A capped gesture can therefore leave more than 5,000 selected IDs; the Set can also contain unrelated prior picks. Soft feedback uses pre-dedup `idsToCommit.length`, not actual changed membership. Preserve the useful bound and endpoint semantics; do not impose the guide's unimplemented hydration truncation or silently lower selection capacity. The 5,000-entry LRU is a separate metadata capacity, so larger selections may have incomplete metadata cohorts.
5. **Order/completeness are not proved by a successful page.** [Comparison](../../../../src/dal/es-adapter.ts#L99) uses host `localeCompare` for string tuple components, while sort construction supplies ES field order and null-last rules. Locale collation is not a demonstrated ES keyword ordering contract; P23 must join actual mapping/configured fields. The collector uses current raw search params, not the browse freeze helper, and no PIT. HTTP-200 execution flags are ignored by its [paging helper](../../../../src/dal/es-adapter.ts#L996); abort can return a partial list with `truncated:false`. A new range gesture's generation currently blocks its aborted predecessor's commit, but `truncated` itself is only cap evidence. Retain amended E033 without pretending its historical map reproducer executed a range case.

Authoritative tuple retention remains valuable: [cache](../../../../src/lib/image-offset-cache.ts#L26) copies current-search tuples, keeps bounded recent entries plus one active anchor, and checks the search key. [Cache assertions](../../../../src/lib/image-offset-cache.test.ts#L85) explicitly show that an API-shaped alias image without retained tuple can reconstruct a null primary. Selection surviving a sort is not proof the new-order tuple is already available to a new range gesture. Preserve complete relationship arrays for selected-max date extraction and retain P23's configured-alias/null-shape join; do not replace tuples with display strings.

**Candidate consequence:** keep S3b client collection over admitted source-free keys, but replace generic "range guards" with endpoint-order/overshoot, actual ES versus mock, stale add/remove/finalization, null crossing, tied-string order, cap/exact-cap and incomplete-result cases. New Grid key pages must expose usable execution/exhaustion/progress without image enrichment. No full-range server job, map slicing or mandatory snapshot is requested.

### F4. Presentation Is Coherent, Not A Universal Full-Selection Metadata Claim

[The route resolver](../../../../src/routes/search.tsx#L303) freezes image references, single/multi mode, reconciled view and totals together while pending; membership stays immediate. It does not freeze the global enrichment Map. [Cost summaries](../../../../src/components/MultiImageMetadata.tsx#L314) derive current overlays per cached image; rights/category reconciliation and lease rows use baseline cached images, while [single metadata](../../../../src/components/ImageMetadata.tsx#L190) uses overlay rights/summary when present. [Usages](../../../../src/components/UsagesSection.tsx#L317) uses buffer-first resolved images, not overlay usages. Thus a coherent pending presentation is not proof all sections share one payload version or policy provenance. The intentional available-image denominators survive failed reads and LRU eviction; do not relabel them exact selected-population counts.

A bounded existing scalar discrepancy affects the same panel: [incremental add](../../../../src/lib/reconcile.ts#L231) turns `all-empty(count > 0)` plus a valued image into `all-same(count:1)`, whereas [full recompute](../../../../src/lib/reconcile.ts#L328) yields mixed with emptyCount. Cached adds can retain this result because no network/full recompute is requested. [Tests](../../../../src/lib/reconcile.test.ts#L178) cover the zero-count version, not this nonzero-empty transition. This is a source-supported presentation inconsistency, not a newly executed failure or a reason to block unrelated Grid operations. A future touched reconciliation slice should first characterize equality between incremental and full results rather than weakening either definition.

Metadata-to-search is now joined through P20's previously unread presentation helpers: [SearchPill](../../../../src/components/SearchPill.tsx#L52), MultiSearchPill, ValueLink and [metadata callback](../../../../src/components/metadata-primitives.tsx#L28) preserve modifier semantics and strip detail `image`; changed queries cancel the shared CQL debounce. ### F5. P19 F4 Is A Hidden-Focus Policy Mismatch, Not A Clear-Focus Fix

The owning [selection guide](../../00%20Architecture%20and%20philosophy/05-selections.md#L409) explicitly retains `focusedImageId` while selection suppresses its ring/panel role, then restores its ordinary role on exit. [Selection sort assertion](../../../../e2e/local/selections.spec.ts#L146) keeps the older focus while anchor B preserves placement, then asserts clear leaves focus and scroll unchanged. This is positive evidence against automatically clearing focus on entry.

The original [keyboard owner](../../../../src/hooks/useListNavigation.ts#L482) computes effective `hasFocus` from stored focus, explicit mode and empty selection. Windowed End nevertheless always queues `last` to achieve end scrolling; [effect 6](../../../../src/hooks/useScrollEffects.ts#L528) tests only stored focus before replacing it with the last resident image. Resident End gates mutation on effective `hasFocus`. With retained hidden focus, these routes can therefore differ; with null stored focus both keep null. Phantom mode can also retain an ID from detail return even though effective focus is false.

The complete [keyboard assertions](../../../../e2e/local/keyboard-nav.spec.ts#L79) cover null-focus End and explicit-focus End, not retained hidden focus plus selection/phantom; the selection suite covers sort/clear, not End in selection. **Disposition:** supported source-only policy inconsistency; preserve hidden focus and tail scrolling, characterize both End routes plus clear/exit and a selection/mode change while seek is pending before choosing an affected client correction. No clearfocus fix, navigation redesign or runtime regression claim follows. P18/P19 request/action clock qualifications remain applicable; S1 did not alter them.

### F6. Collection Tree Absence Is Not Count Completeness Or Freshness

[Store](../../../../src/stores/collection-store.ts#L125) is a distinct once-per-app owner. Tree failure/non-2xx/unexpected root shape returns null; aggregation rejection leaves a successful tree with empty counts. The route hides the whole accordion only after status becomes absent. Both outcomes wait for `Promise.allSettled`; neither request has an explicit timeout, so a stalled count read can delay even known tree absence. There are no normal catch warnings/toasts here. A malformed successful descendant structure is not recursively validated by the root wrapper. Do not claim universal graceful shape handling from the function comment.

Actual count scope is `getAggregations({}, [{field:'collections.pathId',size:6000}])`. [Query construction](../../../../src/dal/es-adapter.ts#L461) still excludes deleted/replaced and applies `FREE_FILTER` because `nonFree` is absent. Consequently "unfiltered" means independent of current search, **not all images**; ordinary default browsing includes paid images via `nonFree=true`. This source mismatch with the owning guide needs an explicit retain-or-correct decision in S8, not silent migration to different counts. Grid must additionally apply admitted principal/tier policy before exposing buckets.

[Subtree accumulation](../../../../src/stores/collection-store.ts#L97) sums each exact-path bucket into ancestor prefixes, including orphan paths. A document in sibling collections contributes twice to their parent; that compromise is explicit and should remain, not be upgraded into a unique-parent exactness requirement. Terms size 6000 is bounded; omitted buckets and ignored HTTP-200 incomplete-execution flags can reduce counts. The adapter returns empty fields for absent aggregations and does not expose bucket-completeness provenance. No current shard/truncation incidence is measured. The guide's historical percentage/PROD-scale claims were read as documentation, not remeasured or independently verified.

**Stale publication has a precise scope.** Counts/tree are persisted; status is not, so reload starts a new boot read while cached tree remains available to grid colour lookup. `loading`/`ready` prevents overlapping normal loads, but there is no request epoch, cancellation, principal/config key or refresh after ready. A delayed boot result still publishes after search/navigation; that is expected for intentionally search-independent counts, not proof of a query-stale bug. It can remain old for the rest of the app session. Any future principal/datasource invalidation or reload facility must guard old tree/count publication and invalidate persisted scope; current source does not implement or certify such a transition. Do not invent an existing logout workflow to demonstrate it.

Counts only render when positive, so empty/missing/zero all produce no badge; absence is not shown as a successful numerical zero. Tree unavailable also removes tree-derived suggestions, but image collection badges/CQL and fallback colours still work. The complete [store tests](../../../../src/stores/collection-store.test.ts#L8) test subtree arithmetic only. [E2E](../../../../e2e/local/collections.spec.ts#L101) mocks tree and allows missing count data; its 503 test establishes route hiding, not count failure, timeout, free/all scope, fresh-principal invalidation or incomplete-response handling.
