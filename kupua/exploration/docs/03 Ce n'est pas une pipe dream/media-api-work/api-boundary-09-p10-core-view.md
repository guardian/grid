### 2.2 Fetch Triggers, Scrollbars and Cancellation

`reportVisibleRange()` publishes the current coordinate-mode range to a module-level external store. It widens only the forward extension threshold using positive velocity; backward extension keeps the fixed threshold. Defaults are page size 200, extension threshold 50, velocity lookahead 400ms and idle reset 250ms. Indexed viewports near the buffer extend; distant viewports debounce a seek for 200ms, canceling it when they return near the buffer. Normal mode tests local edges. [W:71](../../../../src/hooks/useDataWindow.ts#L71), [W:199](../../../../src/hooks/useDataWindow.ts#L199), [W:361](../../../../src/hooks/useDataWindow.ts#L361), [K:24](../../../../src/constants/tuning.ts#L24).

The scroll hook converts grid row ranges to flat image ranges and supplies a near-bottom `loadMore()` fallback. After a seek-generation change it skips one buffer-triggered range report to avoid using the previous virtualizer range. [S:337](../../../../src/hooks/useScrollEffects.ts#L337), [S:382](../../../../src/hooks/useScrollEffects.ts#L382).

The actual scrubber interaction regime is direct scrolling when all data is resident, a map is loaded, **or `twoTier` is true**. Thus map readiness is not a prerequisite for indexed interaction. Direct mode continuously maps native pixel scroll ratio to thumb position and reattaches when the registered container generation changes. Track wheel events are prevented only when forwarding actually moves the content. Seek mode preserves the pending thumb target until position/loading/total catches up; drag moves the thumb without fetching, then invokes one final seek on pointer-up (pointer-cancel uses the same handler). [B:227](../../../../src/components/Scrubber.tsx#L227), [B:355](../../../../src/components/Scrubber.tsx#L355), [B:416](../../../../src/components/Scrubber.tsx#L416), [B:512](../../../../src/components/Scrubber.tsx#L512), [B:611](../../../../src/components/Scrubber.tsx#L611), [B:653](../../../../src/components/Scrubber.tsx#L653).

**Necessary contract:** coalesce redundant intent, allow the latest relevant request to win, and prevent canceled/old-context fetches from committing into a newer window. Completion must leave enough state to resume gap detection and traversal; a successful request must not leave `loading` or an extend blockade permanently pending. These hooks issue fetches without awaiting them, so they rely on store ownership of overlap, abort and stale-result checks. In particular, W's delayed seek captures an old `globalStart` and calls the current seek ref; W has no query-generation check in that callback. Join its lifetime with search/reset ownership before claiming complete cancellation coverage. This is a dependency question, not a reproduced defect or a requested repair.

Timing constants are client scheduling values, **not API latency guarantees**. K currently defines seek cooldown 100ms, deferred scroll 150ms, post-backward-extend cooldown 50ms and search-fetch cooldown 2,000ms. S calls `abortExtends()` before deferred density restoration; the actual store implementation of that call remains P09-owned. [K:136](../../../../src/constants/tuning.ts#L136), [K:181](../../../../src/constants/tuning.ts#L181), [S:904](../../../../src/hooks/useScrollEffects.ts#L904). A comment saying a request usually finishes within a particular interval is not measured evidence here.

### 2.4 Focus, Selection, Density and Panel Reflow

Before a non-display URL transition, S captures a sort-placement ratio from selection anchor for sort-only transitions, otherwise explicit focus, otherwise a viewport anchor for non-sort transitions. Pure phantom sort-only navigation intentionally has no such preservation. Selection lookup failure in this path is not automatically the same fallback policy as grid resizing; preserve the distinction. The later placement consumes `_phantomFocusImageId` once. [S:574](../../../../src/hooks/useScrollEffects.ts#L574), [S:619](../../../../src/hooks/useScrollEffects.ts#L619), [S:749](../../../../src/hooks/useScrollEffects.ts#L749).

Small-result first-page bottom clamping retains a pending placement only for local mode, origin zero, total within the small threshold, incomplete fill and an unreachable intended position. On growth it retries; changed PIT/seek generation, focus, pending navigation, loading, shrinking results, origin or scroll position invalidates it. Later user intent wins. [S:738](../../../../src/hooks/useScrollEffects.ts#L738), [S:831](../../../../src/hooks/useScrollEffects.ts#L831). This permits phased results without forcing the API to withhold every first page until a whole small set is ready.

Density unmount saves a **global index**, viewport ratio, source scroll position and extrema. Mount peeks rather than prematurely consumes it, aborts extensions, waits two animation frames for real geometry, re-derives local position from the current origin, and applies edge clamps/snaps. Home can suppress the save; Strict Mode cleanup must not overwrite an unconsumed save. This bridge uses explicit focus then viewport anchor, **not selection-first density anchoring**. [S:51](../../../../src/hooks/useScrollEffects.ts#L51), [S:858](../../../../src/hooks/useScrollEffects.ts#L858), [S:1042](../../../../src/hooks/useScrollEffects.ts#L1042).

Grid panel/window reflow is a separate capture-before-resize, restore-before-paint path. It skips anchor capture on the initial column correction. Candidate precedence is resolvable active selection anchor, explicit focus, lazy viewport anchor, then arithmetic fallback. It does not create focus for the selection. [G:463](../../../../src/components/ImageGrid.tsx#L463), [G:526](../../../../src/components/ImageGrid.tsx#L526), [G:600](../../../../src/components/ImageGrid.tsx#L600), [R:68](../../../../src/lib/grid-scroll-anchor.ts#L68).

**Exact versus approximate:** identity/global-index translation is discrete; placement uses floor-to-row, ratios, clipping correction and extrema snaps, so it is not universal pixel identity across densities. Reflow fallback is explicitly approximate. Even when the anchor is a real image, phantom reelection need not choose the same identity on both legs of a panel round trip. R's historical live claims were read only as comments, not independently checked measurements. Table uses measured header height and a custom usable-area centering callback; font/header/layout owners still matter. [T:531](../../../../src/components/ImageTable.tsx#L531), [T:763](../../../../src/components/ImageTable.tsx#L763).

### 2.5 Keyboard, Detail and Traversal Landing

Grid and table detail entry set focus, translate their lookup index to a global offset, retain a search-keyed cursor, and push navigation with immutable `_detailEntryImageId`. Selection gestures prefer retained anchor sort values before reconstructing from cached metadata. The required identity/tuple provenance is real; P10 does not infer the correctness of `extractSortValues`, tuple retention or history storage from these calls. [G:674](../../../../src/components/ImageGrid.tsx#L674), [G:700](../../../../src/components/ImageGrid.tsx#L700), [T:570](../../../../src/components/ImageTable.tsx#L570), [T:669](../../../../src/components/ImageTable.tsx#L669).

The inspected keyboard implementation uses rows/pages when no effective focus or when selecting, focused-index movement otherwise, and ignores list keys during detail/fullscreen or native input editing. Off-buffer focus stores `_pendingFocusDelta` before `seekToFocused()`; S consumes the delta directly into one centered landing rather than first scrolling to the old focus. Home/End pend edge intent when a seek is needed, avoiding an eager old-buffer scroll reset. Placeholder skipping is bounded at ten positions; this is not a promise of unlimited synchronous navigation through unloaded slots. [N:184](../../../../src/hooks/useListNavigation.ts#L184), [N:261](../../../../src/hooks/useListNavigation.ts#L261), [N:387](../../../../src/hooks/useListNavigation.ts#L387), [N:482](../../../../src/hooks/useListNavigation.ts#L482), [S:787](../../../../src/hooks/useScrollEffects.ts#L787).

`useImageTraversal` works exclusively in global indices across tiers. Resident adjacent images navigate immediately. Near-edge navigation triggers proactive extension only after navigation has occurred; an absent neighbor records one pending direction and requests extend or seek. Publication of `results`/`bufferOffset` resolves the pending direction relative to the current image. An inactive/null session clears pending direction and proactive eligibility. Therefore the ordered window and image-position lookup must keep the current image resolvable through a pending adjacency operation; stale data must not complete navigation in a later context. Request/session cancellation beyond the null reset is a caller/store join, not verified here. Image prefetch is called but not inspected. [V:80](../../../../src/hooks/useImageTraversal.ts#L80), [V:104](../../../../src/hooks/useImageTraversal.ts#L104), [V:151](../../../../src/hooks/useImageTraversal.ts#L151), [V:189](../../../../src/hooks/useImageTraversal.ts#L189), [V:221](../../../../src/hooks/useImageTraversal.ts#L221).

Detail return compares the closing image with the immutable entry image, restoring focus and centering only when traversal changed the image; phantom mode can pulse the returned image. Home suppression and intentional explicit-focus clearing prevent restoration from undoing a reset. S separately registers centered fullscreen-exit positioning. **Required behavior:** preserve entry-versus-last-viewed identity, correct coordinate conversion and current data at exit. **Not implied:** persistent server browsing sessions or a new history model. Overlay layout preservation and fullscreen/history callers remain unread owners. [Q:79](../../../../src/hooks/useReturnFromDetail.ts#L79), [Q:98](../../../../src/hooks/useReturnFromDetail.ts#L98), [Q:145](../../../../src/hooks/useReturnFromDetail.ts#L145), [S:289](../../../../src/hooks/useScrollEffects.ts#L289).

### 2.6 Rendering and Supporting Workflows Are Part of the Contract

Both views consume normalized application `Image` objects plus per-image optional enrichment. Missing indexed slots are identity-less placeholders, not selectable images. Table has a lightweight preview if an image is loaded before its TanStack row exists; that path directly reads `image.metadata`. An API adapter must preserve the application's image shape, IDs and usable media/metadata fields, not simply substitute a differently shaped response envelope. Enrichment arrival should not redefine positional ordering. [G:210](../../../../src/components/ImageGrid.tsx#L210), [T:403](../../../../src/components/ImageTable.tsx#L403), [T:423](../../../../src/components/ImageTable.tsx#L423).

Grid intentionally uses positional cell keys; table limits row-model work to visible/overscan images, caches the first-ID/last-ID/count sentinel, and freezes row/virtual-item inputs during column resizing while widths update through CSS variables. The sentinel does **not** compare every middle identity or same-ID metadata revision. This is an existing presentation assumption to account for if a future API changes publication shape; it is not authority to require immutable metadata or universal snapshots. No new performance conclusion or repair follows.
