Changing default fields/fuzziness is an actual operator/maintainer decision, not automatically authorized Grid parity. |
| Deleted/replaced defaults | Client API injection and direct builder use case-sensitive substring checks. POST uses parsed intent; [controller](../../../../../media-api/app/controllers/MediaApi.scala#L876) scopes positive deleted intent by principal. Quoted/uppercase positive intent can acquire a contradictory negative clause in the mapper. | Nested usage matching | Positive clauses share one nested record, negative clauses share a separate negated nested record. | `is:` and named counts | Client supports ownership, deleted, quota and configured agency-pick, not reapable semantics; unknown `is:` returns non-negated match-none even for a negative input. | Click/edit quoting | [AST upsert](../../../../src/dal/adapters/elasticsearch/cql-query-edit.ts#L157) uses case-insensitive key/value identity and quotes whitespace/colon/parentheses; it does not escape embedded quotes. [Plain metadata click](../../../../src/components/metadata-primitives.tsx#L28) quotes only spaces. Unknown/invalid syndication strings are another explicit admission case: [client test](../../../../src/dal/syndication-filter.test.ts#L72) ignores uppercase/unknown, [server model](../../../../../common-lib/src/main/scala/com/gu/mediaservice/model/SyndicationStatus.scala#L16) lowercases then matches without a default.

### F4. Identity And Edited-Date Provenance Are Now Joined

Direct query IDs filter the source `id`; API `filters.ids` uses `_id`. The normal [ImageMessage](../../../../../common-lib/src/main/scala/com/gu/mediaservice/model/ThrallMessage.scala#L95) derives its ID from image.id; [processor](../../../../../thrall/app/lib/kinesis/MessageProcessor.scala#L67) forwards it, and directInsert also uses image.id. However, the general [upsert](../../../../../thrall/app/lib/elasticsearch/ElasticSearch.scala#L95) accepts an independent ID; an [existing assertion](../../../../../thrall/test/lib/elasticsearch/ElasticSearchTest.scala#L24) deliberately indexes a different source ID under the requested document ID and retrieves it. The [old deviation's universal equality wording](../../deviations.md#L1140) is therefore a normal-ingest expectation, not an enforced storage invariant or live-corpus finding. Decide the supported identity assumption and whitespace/empty-ID policy before claiming API lookup equivalence; do not require reindexing or migration support.

The actual metadata timestamp path is [EditsController](../../../../../metadata-editor/app/controllers/EditsController.scala#L156) -> [EditsStore](../../../../../metadata-editor/app/lib/EditsStore.scala#L6) -> [Dynamo update](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/aws/DynamoDB.scala#L212), which writes the configured `lastModified` alongside the update and returns all new attributes. [Edit.publish](../../../../../metadata-editor/app/lib/Edit.scala#L14) embeds the parsed Edits; [UpdateMessage](../../../../../common-lib/src/main/scala/com/gu/mediaservice/lib/aws/ThrallMessageSender.scala#L68) separately has an event timestamp. [Translator](../../../../../thrall/app/lib/kinesis/MessageTranslator.scala#L36) and processor preserve both. [Thrall applyImageMetadataOverride](../../../../../thrall/app/lib/elasticsearch/ElasticSearch.scala#L241) prefers edits.lastModified, falls back to event time, guards user metadata by userMetadataLastModified, and uses [monotonic root update](../../../../../thrall/app/lib/elasticsearch/ElasticSearch.scala#L790). [Assertions](../../../../../thrall/test/lib/elasticsearch/ElasticSearchTest.scala#L626) cover both timestamps and older-edit suppression.

Thus root `lastModified`, root `userMetadataLastModified` and nested `userMetadata.lastModified` are distinct. Root time is also set at ordinary insertion and updated by other event paths; it is not simply "last human edit", nor is absence proof of never edited. Embedding update explicitly does not use the modification-updating wrapper. Normalized metadata is already merged server-side; S1 preserves it instead of rebuilding it from nested edits. This is provenance inspection only: no mutation path was invoked and migration branches confer no implementation mandate.
