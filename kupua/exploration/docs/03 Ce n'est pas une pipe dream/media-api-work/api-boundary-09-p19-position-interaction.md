## 2. Material Findings

### F1. Coordinate Choice Is Independent of Map Availability

The same total predicate controls [data access](../../../../src/hooks/useDataWindow.ts#L329), [route props](../../../../src/routes/search.tsx#L140), [geometry conversion](../../../../src/hooks/useScrollEffects.ts#L45) and ordinary [seek publication](../../../../src/stores/search-store.ts#L3721). The source defaults are 1,000 and 65,000, not endpoint limits; [tuning](../../../../src/constants/tuning.ts#L70) permits overrides, and zero disables the indexed tier. Actual deployed overrides are P23-owned, not read from private configuration here.

| Tier | Action, request and publication | Rendered coordinate consequence |
| --- | --- | --- |
| Small, at most 1,000 by default | First exact-total page publishes, then [fill](../../../../src/stores/search-store.ts#L1013) appends cursor pages. Direct Scrubber scrolling starts only when `total <= bufferLength`, not merely when total is small. Centred focus/restore instead drives bounded top-up through existing extends. | Local indices and resident-length virtualizer; incomplete small fill may still use seek interaction. Top-up's `_bufferSelfCorrecting` protects the already placed viewport from the offset-zero Home guard. |
| Indexed, above 1,000 through 65,000 | Scrubber scrolls the actual container even with map null; [distant range reporting](../../../../src/hooks/useDataWindow.ts#L391) debounces seek, near ranges extend. A background map changes seek routing, not coordinate space. | Virtualizer count is total from the first publication. Grid uses global row/column positions; table uses global row indices. Out-of-buffer slots are identity-less skeletons. |
| Deep or indexed disabled | [Pointer drag](../../../../src/components/Scrubber.tsx#L653) previews without seeking until release; track click immediately requests seek. Wheel remains native content scrolling. Store publishes a bounded replacement with actual origin, tuples and target generation. | Local indices plus buffer origin form global position. Bidirectional landing supplies headroom; later prepend/eviction requires compensation. |

The Scrubber's internal `scrubberMode` label is not the interaction decision: [the actual predicate](../../../../src/components/Scrubber.tsx#L227) is buffer-complete **or** map-loaded **or** `twoTier`. Route `currentPosition` is the visible start directly in indexed mode, otherwise visible start plus origin; visible count is at least one. Pointer mapping uses `total - visibleCount` and thumb travel; direct-mode thumb sync uses the actual scroll-pixel ratio and [container generation](../../../../src/lib/scroll-container-ref.ts#L33) to reattach after density switches. Pending seek preview clears on total change, position change or loading completion. None of these signals identifies a history entry.

**Candidate consequence:** retain sections 2/5's total-driven invariant and clarify the incomplete-small-fill transient. Do not wait for maps before rendering indexed coordinates, ship geometry/React generations as API fields, or require a new count on every continuation. Replacing the shallow transport must preserve offset, hit/tuple alignment and retained session-total ownership together.

### F4. Keyboard, Anchoring and Geometry Must Retain Their Existing Distinctions

[Keyboard input guarding](../../../../src/lib/keyboard-shortcuts.ts#L95) exempts opted-in navigation inputs; list handlers stop during detail/fullscreen. Page movement uses usable height; explicit arrows preserve columns where possible, with only a bounded ten-slot placeholder skip. These are client policies, not requests for an unbounded API seek per key. Scrubber itself has slider ARIA but no own keyboard handler/tab stop in its complete JSX; list keyboard handling supplies navigation. Do not credit stale comments mentioning Scrubber keyboard callbacks as executed behavior.

Grid reflow is selection-first with fallback if the selected anchor is unresolved. Density save is focus-first then DOM anchor, not selection-first. Table uses 32px rows, measured header (36px fallback), usable-area centring and horizontal-scroll preservation on sort. [CSS](../../../../src/index.css#L241) supplies strict containment; grid cell/row dimensions are fixed. These paths cannot be collapsed into one unconditional pixel-equality rule. [Pure resize assertions](../../../../src/lib/grid-scroll-anchor.test.ts#L43) prove exact arithmetic only for stable identity; fallback/re-elected phantom anchors remain approximate. [Extended store assertions](../../../../src/stores/search-store-extended.test.ts#L1171) separately test current-column trim after settled and in-flight resize.

**Precise P21 join:** windowed End always writes `_pendingFocusAfterSeek:'last'` to obtain tail scrolling, even when `hasFocus` is false because selection/phantom mode suppresses focus navigation. [Effect 6](../../../../src/hooks/useScrollEffects.ts#L528) then tests only whether `store.focusedImageId` exists, not the original effective mode/selection predicate, before changing it to the last resident image. The already-resident End branch uses `hasFocus`. Thus with retained hidden focus, pending and resident End can differ in hidden-focus mutation. This is source composition, not a reproduced selection UX defect; ask P21 to disposition the retained-focus contract and assertions, not automatically clear focus or change selection policy.

One related P18 integration note: [table header sort](../../../../src/components/ImageTable.tsx#L1146) delays 250ms with a captured sort callback; cleanup cancels on table unmount, not a same-mounted URL/history change. It shares P18's pending-action question but is not a reason to add a global navigation state machine or repair unrelated input behavior now.
