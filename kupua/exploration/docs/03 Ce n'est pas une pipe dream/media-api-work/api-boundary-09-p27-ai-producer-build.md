### F1. Producer Failure and Eligibility Details

The live queue payload is plain JSON `{imageId,fileType,s3Bucket,s3Key}`, not an SNS envelope, vector or image metadata. The consumer casts parsed JSON; it has no schema/version/rights validation. The selected loader has already produced source/optional optimised assets and emitted the image notification when it queues embedding. These are different asynchronous downstream paths; source order alone is not proof that the ES image exists when the embedding update arrives. The projector's [selected construction path](../../../../../image-loader/app/model/Projector.scala#L153) accepts `maybeEmbedder` but does not call it in `projectImageFromUploadRequest`; do not infer requeue-on-reprojection from that constructor argument. Other ingestion/reprojection workflows are outside this bounded normal-upload trace; reopen only for a selected workflow requiring that guarantee.

Backfill's static filter is an OR of free categories, suppliers without exclusions and supplier-with-excluded-collection clauses. Its comment says it copies Guardian rights configuration; P23/P24 already establish alternative runtime providers. This is an explicit producer scope, not automatically a bug in current Grid search policy. Source URL parsing assumes the bucket is the first hostname label and the key is the slash-stripped URL pathname. The test named 'path-style URL' actually supplies a virtual-hosted URL; it does not prove arbitrary S3 URL support. No current canonical-upload failure is inferred from that mislabeled test.

The byte cache is not vector storage. Pixel-oversized cached images are treated as misses; acceptable cached pixels still pass the byte/pixel resize check. There is no expiry/source revision key; cache MIME is inferred from the queue type. Resize uses one pixel-ratio-derived width, JPEG quality 95 or PNG compression 9, then checks resulting byte length. Byte-only oversize can cause enlargement because the width factor uses only the pixel ratio; this is a source qualification, not a measured quality/cost defect. The narrower zero-width case is actionable below. The model request's image data URI is base64, while the size check is on raw bytes.

`generateVectors` processes records serially, catches parse/fetch/decode/model failures per SQS message, and returns those IDs for retry. Successful vectors have a single image-ID-to-message-ID map entry per image; duplicate IDs overwrite that attribution and are not coalesced. Kinesis response cardinality mismatch or send failure throws the invocation; individual Kinesis errors add mapped message IDs to the partial failure list. S3 Vectors is attempted even for vectors whose Kinesis item failed; a thrown S3 write aborts the invocation after Kinesis may already have accepted records. This permits repeated model calls and publication; no atomicity/dedup/exactly-once claim is supported. It is not proof of lost live vectors. [Publisher](../../../../../image-embedder-lambda/src/embedder/thrallEventPublisher.ts#L78) creates a fresh timestamp and uses image ID as partition key; Thrall overwrites the embedding without comparing that timestamp.

Assertions read: backfiller tests cover missing fields, empty hits, ES error, URL extraction and crowded-queue skip; the purported exact-threshold test hardcodes 20 although the current threshold is 4000. Queue tests cover chunking/serialization and queue attributes. Fetch tests exercise JPEG/PNG/TIFF resolution with synthetic byte streams, not Sharp/model acceptance. Resize tests assert concrete ordinary-aspect JPEG/PNG dimensions/bytes. Snapshot test compares a **TEST** synthesized template to checked-in text; it is not a PROD runtime or artifact test. None was executed. No fixture assets or integration helpers were opened or invoked.
