## 2. Material Findings

### F1. Three Identities Compose on Settled Paths

**Source facts:** `kupuaKey` identifies a history entry; `buildSearchKey` identifies query/sort/filter context; `_searchGeneration` and captured abort signals identify asynchronous search work. They are different identities, not interchangeable session IDs.

- [history-key.ts](../../../../src/lib/orchestration/history-key.ts#L69) preserves the current browser state/key on replace and mints a fresh key on push. [Push helpers](../../../../src/lib/orchestration/search.ts#L319) capture the predecessor before navigation. [SearchBar](../../../../src/components/SearchBar.tsx#L78) groups overlapping CQL/AI edits into one typing entry, then replaces it on settlement.
- [URL sync](../../../../src/hooks/useUrlSearchSync.ts#L145) strips display-only image/density keys for dedupe, consumes the navigation flag even on dedupe and refreshes the departing key. Search-affecting changes replace all URL-managed store keys, not just present ones. [Serialization](../../../../src/lib/plain-search-serializer.ts#L25) preserves string values; [canonicalization](../../../../src/lib/search-params-schema.ts#L135) retains one recognized semantic sort and resolves collection/AI conflicts.
- [Snapshot capture](../../../../src/lib/build-history-snapshot.ts#L35) elects explicit focus or a viewport anchor, stores its global offset and geometry-derived viewport ratio, and includes `newCountSince`. [Snapshot storage](../../../../src/lib/history-snapshot.ts#L115) is per-tab, bounded to 50 entries, with unavailable/corrupt-storage degradation. It is not durable server state and contains neither a retained total nor a saved tuple.
- [Popstate](../../../../src/hooks/useUrlSearchSync.ts#L251) captures the departing entry before replacing params, avoids same-anchor phantom-ratio drift, requires a strict search-key match and passes identity/offset/ratio to ordinary `search(anchor, options)`. [Startup/pagehide](../../../../src/main.tsx#L30) disables native scroll restoration, synthesizes an entry key and persists the current snapshot. Image-only and density-only Back/Forward bypass this search path.

**Decision consequence:** preserve these client owners and key formats initially. Grid needs aligned query-scoped data, not browser entry keys, viewport ratios or React generations. The URL key deliberately excludes pagination/display state; [tuple retention](../../../../src/lib/image-offset-cache.ts#L26) separately associates copied authoritative tuples with the raw search key, bounds recent tuples to twice buffer capacity and retains one active anchor. [Grid detail entry](../../../../src/components/ImageGrid.tsx#L674), [table detail entry](../../../../src/components/ImageTable.tsx#L570) and [detail traversal](../../../../src/components/ImageDetail.tsx#L290) persist the tuple and global offset before navigating. Fallback extraction is not proof that API display aliases reconstruct physical sort fields.

### F3. Ordinary Assertions Do Not Refute E013, E014 or E017

**E013, source plus assertion comparison:** [_loadBufferAroundImage](../../../../src/stores/search-store.ts#L1393) returns the forward page total. [Restore](../../../../src/stores/search-store.ts#L3919) chooses indexed targeting from that value but publishes `get().total`. [Direct paging](../../../../src/dal/es-adapter.ts#L976) requests totals only on explicit opt-in and substitutes zero when absent; the [current API request](../../../../src/dal/grid-api-search-adapter.ts#L123) still derives `countAll` from cursor absence and passes the response total through. P17's original server inspection already established API zero totals. [The consumer](../../../../src/hooks/useScrollEffects.ts#L482) falls back to the local target when the global target is negative, while [useDataWindow](../../../../src/hooks/useDataWindow.ts#L343) remains indexed from session total. Thus the conditional coordinate mismatch is source-backed on both transports. An actual visible loop, incidence or duration is **not** established here; the per-image attempt guard also prevents casually inheriting the old comment's infinite-loop claim.

The [ordinary centred restore](../../../../src/stores/search-store.test.ts#L2419) and [small-set fill restores](../../../../src/stores/search-store.test.ts#L1919) use 1,000/700-image mocks, not an indexed session with an untracked page. [Mock continuation](../../../../src/dal/mock-data-source.ts#L604) supplies the corpus total regardless of count intent. The 30,000-image cancellation/enrichment and PIT cases exercise different assertions, not zero-total coordinate placement. The exact future check is a retained indexed total, nonempty forward/backward pages with zero totals, map absent/present, and a global target matching the published image. Do not request exact counts on every continuation as the fix.

**E014:** [saved rank/current neighbours](../../../../src/stores/search-store.ts#L3877) remains unchanged. The [special-date restore assertion](../../../../src/stores/search-store.test.ts#L2408) explicitly expects the supplied saved cursor in `countBefore`; it verifies tuple forwarding, not changed-metadata coherence. Default mock rank resolves an ID to its original index ([mock](../../../../src/dal/mock-data-source.ts#L619)), while stable centred tests use an unchanged tuple. A separately authorized correction must first characterize changed sorted metadata and intentionally update this old-behaviour assertion if ranking switches to the effective landing tuple. No universal snapshot is needed to ask rank and neighbours to use the same selected tuple.

**E017:** [restore catch](../../../../src/stores/search-store.ts#L3967) treats non-AbortError failure as `seek(cachedOffset)`; [shallow seek](../../../../src/stores/search-store.ts#L2928) supplies a positive offset without PIT/cursor; [Strangler](../../../../src/dal/strangler-adapter.ts#L55) bypasses API for that shape. [Adapter assertions](../../../../src/dal/strangler-adapter.test.ts#L72) correctly prove no adapter fallback on refusal, but do not invoke store recovery. The [PIT refusal fixture](../../../../src/stores/search-store-pit.test.ts#L137) asserts cleared PIT/loading, not no follow-up ES request. A future composed refusal assertion must include the real store and adapter boundary. Retain supported hybrid development, no live authorization-bypass claim, and no restart of D3 readiness.

### F4. Request Guards Do Not Own Every Pending User Action

**Supported source facts, conditional runtime consequences:** successful stale search/focus/seek/restore results are guarded before tuple/enrichment publication. The [ordinary cancellation tests](../../../../src/stores/search-store.test.ts#L869) deliberately release cancelled pages and check no enrichment corruption; [search abort assertions](../../../../src/stores/search-store.test.ts#L1282) inspect the passed signal. [PIT tests](../../../../src/stores/search-store-pit.test.ts#L351) cover stale successful open cleanup. These are read tests, not newly executed proof of every failure path.

Two pending-navigation boundaries are outside those guards:

1. **Debounced input is not entry-bound.** [SearchBar](../../../../src/components/SearchBar.tsx#L78) captures text and later invokes `updateSearch(..., {replace:true})`; [the update helper](../../../../src/hooks/useUrlSearchSync.ts#L419) uses current params/key at invocation. Neither timer captures/checks its originating entry key. URL sync does not cancel it on Back. Home cancels the shared CQL timer, but **not SearchBar's local AI timer**; [Clear](../../../../src/components/SearchBar.tsx#L128) does cancel both. SearchBar stays mounted on the search route; remounting its input children does not cancel its local timer. If Home completes or Back changes entry before the pending callback, old text can replace the destination entry and begin a new, perfectly current search. Store generations cannot reject an action that has not yet issued a request. Existing typing tests settle edits before Back; the overlap test checks two concurrent editors, not navigation during debounce. P22 should join the actual AI widget event lifecycle; no runtime failure is asserted here.
2. **Home's post-await navigation is unconditional.** [resetToHome](../../../../src/lib/reset-to-home.ts#L131) awaits `search()` then calls `navigate()` without a Home/search/entry ownership check. [A superseded search returns normally](../../../../src/stores/search-store.ts#L2298), so a newer user navigation while Home is pending can be followed by the older Home callback. Its dedupe/suppression state is also module-level. The [Home unit test](../../../../src/lib/reset-to-home.test.ts#L45) asserts one search and navigation using an immediately resolved mock; it does not gate/reorder competing work. This is a source-supported race precondition, not a reproduced UX symptom.

Additionally, generic [restore](../../../../src/stores/search-store.ts#L3967) and [seek](../../../../src/stores/search-store.ts#L3817) catches distinguish AbortError but do not separately test the captured signal for a late non-abort rejection. Preserve the producer cancellation contract when introducing nullable/typed API failures; do not claim every rejected stale operation is currently harmless. Existing API/Strangler wrappers explicitly recheck cancellation, which narrows rather than removes the caller requirement.

**Smallest consequence:** add entry-action supersession to candidate acceptance obligations and characterize these bounded cases before changing their owners. Do not block every additive Grid slice on a new generic history state machine. These are client-local issues that API migration must not hide behind a claim of universal cancellation. New bounded checks need authorization; no test or repair was performed.

### F5. Return and Geometry Have Precise Remaining Joins

[Return assertions](../../../../src/hooks/useReturnFromDetail.test.ts#L187) cover traversed close, reload with focus equal to the closing image, unchanged native position, Forward rebasing and stale Home suppression. Their animation-frame stub is synchronous ([setup](../../../../src/hooks/useReturnFromDetail.test.ts#L86)); it cannot establish supersession safety of the real deferred centring callback. The hook computes a row then schedules an uncancelled callback, without rechecking search/entry identity. P20 owns its interaction with close/reopen, traversal and fullscreen; P19 owns geometry changes before that frame.

[useDataWindow's delayed scroll-seek](../../../../src/hooks/useDataWindow.ts#L413) captures a global offset, but runs the current seek ref; `resetVisibleRange` does not cancel the module timer. [Density restore](../../../../src/hooks/useScrollEffects.ts#L915) cancels frames on unmount but does not carry a search identity. These are the already-open P10 deferred-work joins, now checked against the complete store and Home owners. A later `seek` cancels requests that exist then; that does not automatically invalidate an older timer issuing a new request. P19 must disposition these interleavings, not simply count the helper as read.

The [history E2E file](../../../../e2e/local/browser-history.spec.ts#L1108) asserts exact traversed identity and usable-centre placement after eviction/reload/close, then reverse traversal after Forward. Other cases cover entry keys, predecessor snapshots, query/sort restoration, phantom cycles, Home departure, deep-link synthesis and reload. [Shared fixtures](../../../../e2e/shared/helpers.ts#L25) block `/api/**` by default; [seek settlement](../../../../e2e/shared/helpers.ts#L531) tolerates some timeouts; `getFirstVisibleImageId` actually reads buffer element zero. Assertions range from URL/focus/offset checks to actual viewport/decode checks, not universal all-tier/API proof. Existing successful S1 local gates remain **historical execution recorded in candidate 11**, not a P18 run or live API restore certification.

### F6. Grid and Shared-Caller Consequences

No new Grid endpoint is justified by browser entry identity. Keep candidate window/rank/keys/context contracts, aligned image/tuple results, explicit total availability and caller-owned publication. E013 needs client total interpretation; E014 needs a same-effective-tuple disposition; E017 needs caller-plus-adapter failure semantics before claiming API-only operation. Do not change GET, Kahuna history, shared Scala execution, D3 wire zero or S1 normalization to repair these client boundaries. New API window/rank work still needs P23 query/mapping and P24 admission/completion joins. This packet does not independently recertify their server originals or deployed load. Existing measured core remains the baseline; new transports are not performance-certified by these reads.
