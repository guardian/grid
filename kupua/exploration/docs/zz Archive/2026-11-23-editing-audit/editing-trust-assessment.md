# How much should we trust editing in Kupua?

Archived assessment. For current guarantees and open work, see the [editing roadmap](../../gradually-growing-teeth.kupua-edits-steps.md).

23 November 2026, checkout `efbbe024e`. Companion reports: [correctness and data integrity](editing-integrity-ledger.md), [performance](editing-cost-ledger.md).

**Recommendation:** keep using the connected editor for bounded, supervised work. A user can type through a slow save, change selection without retargeting an admitted operation, and distinguish many partial outcomes that a simple success toast would hide. Do not interpret this as certification for simultaneous independent writers, general shared-service batch rollout, or deletion. Those are three different decisions. In particular, a second user changing a *different* metadata field on the same image can still undo the first user's edit. A faster queue or a longer visibility poll does not fix that.

## One save, end to end

1. **Intent.** In Details the draft belongs to the open editor; a dirty draft guards departure. In Form, scalar drafts belong to `(image ID, field, revision)`, not a mounted card. Composition pauses autosave; blur or a 600 ms pause can flush it. A completion may clear only the revision it submitted. A batch arrow captures the other known members of the open batch, not the visible cells, the source image or later arrivals. [Details](../../../../src/components/DetailsDrafts.tsx#L16), [Form](../../../../src/components/MetadataTextEditor.tsx#L94), [revision check](../../../../src/stores/metadata-drafts-store.ts#L16), [arrow](../../../../src/components/MetadataEditing.tsx#L107).
2. **Admission.** The providers in [main](../../../../src/main.tsx#L84) connect only in API mode with the startup preference. Both editors share a queue. Selected-label admission normally requires the whole captured selection's authority; the metadata store instead preflights groups, excludes unresolved/ineligible IDs, and can progress with eligible ones. Those behaviors are not interchangeable. An `edits` link is an image-specific grant, not a global session permission. A lease also needs the matching fresh named action. Laptop requests have proxy constraints; hosted requests use discovered service origins directly. The receiving service is the security boundary. [Label admission](../../../../src/stores/label-editor-store.ts#L52), [metadata preflight](../../../../src/stores/metadata-editor-store.ts#L304), [target validation](../../../../src/dal/grid-api/proxy-target.ts), [Grid capability producer](../../../../../media-api/app/lib/ImageResponse.scala#L158).
3. **Dispatch.** Deduplicated IDs survive navigation. Large jobs run in groups. Unsent work can be stopped; a started request cannot be recalled. A queued successor touching the same image may use the predecessor's returned override fingerprint to reject a stale source read. A bulk group can lend a turn to a waiting scalar autosave under specific ownership conditions. None of these structures is shared with another tab. [Store](../../../../src/stores/metadata-editor-store.ts#L265), [scheduler](../../../../src/lib/batch-execution.ts#L28), [source comparison](../../../../src/lib/grid-commands.ts#L237).
4. **Receipt.** Not sent, unchanged, acknowledged, rejected, partial and unknown are not synonyms. An ambiguous response after dispatch is not automatically replayed. Authentication expiry stops subsequent work; some already-started work can still finish. Seeing the requested value does not retroactively turn an unknown command into an acknowledged one. [Classification](../../../../src/lib/grid-commands.ts#L135), [observation](../../../../src/lib/metadata-edit-execution.ts#L140), [issue display](../../../../src/components/EditIssueDisclosure.tsx#L7).
5. **Publication.** A required by-ID read throws on transport failure; missing members in a successful response are omitted. The observer checks expected values against returned identities. It applies read-order and projection checks; a currently open standalone detail needs its own full projection. Verified images update matching resident slots, selected metadata and enrichment without pretending the whole search has been re-ranked. A stale body and a withdrawn action are different problems. [By-ID adapter](../../../../src/dal/grid-api-search-adapter.ts#L197), [freshness](../../../../src/lib/image-read-freshness.ts#L263), [publication](../../../../src/lib/image-publication.ts#L69), [position contract](../../gradually-growing-teeth.step-4-publication-plan.md).

## Comparison with Kahuna

Kahuna is not a transactional baseline. Its [edit service](../../../../../kahuna/public/js/edits/service.js#L157) groups updates for a resource, computes differences from effective metadata, and waits for an image satisfying a matcher. Its [lease service](../../../../../kahuna/public/js/services/api/leases.js#L52) also calls replace/add/remove and polls. The proven parts worth preserving are user intent, owning resources, visible progress and meaningful postconditions. The inherited whole-map and lease service semantics remain the same even if Kupua's UI is more careful.

Kupua makes useful improvements for a single busy editor: captured offscreen membership, per-target receipts, explicit uncertainty, per-revision drafts, and checks against stale authority or stale replacement bases. The price is several different clocks: draft revision, queue ownership, service acknowledgement, projection visibility and current view generation. The complexity is justified where one clock cannot substitute for another. The weak point is that consumers still reconstruct what a save means from combinations of states and optional fields. For the next operation, define the outcomes that a user needs first; do not copy the label matcher and merely substitute a new URL.

## Before connecting deletion

Keep ordinary soft deletion separate from Kahuna's [exceptional takedown](../../../../../kahuna/public/js/takedown/delete-from-grid-step.tsx#L199). For a first single-image deletion, the acceptance case should freeze the exact ID, recheck the current action and server eligibility, and distinguish rejection, uncertain dispatch, recorded soft-delete status and eventual disappearance from search. A filtered-out image, hidden image, failed read or missing by-ID member is **not** affirmative proof of deletion. The current handler returns before its persistence future completes ([GRID-012](../../bug-backlog.md#grid-012)); ordering with undo is separately tracked as [GRID-010](../../bug-backlog.md#grid-010). Do not publish a permanent deleted slot from a 202 alone. No hard deletion or bulk deletion follows from the single-image case.
