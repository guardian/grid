# Editing performance: costs, evidence and priorities

Archived investigation, not a performance work queue.

23 November 2026, `efbbe024e`. Read alongside the [trust assessment](editing-trust-assessment.md). **Do not raise writer concurrency on the evidence here.** The local client is often competitive with Kahuna. Shared Grid capacity, responsiveness while editing, and the cost of retaining operation history are different questions. No fresh benchmark, live service traffic or shared-cluster inspection was performed for this ledger.

## Follow-up dispositions (working tree)

- **P1:** keep the current concurrency. Shared capacity evidence and any rollout exception belong to the service owner; no remote load or infrastructure check was run.
- **P2:** actual metadata-store `submit` with fixture histories, queue dispatch held and 100 new-revision submissions to one image: 2.47 ms with zero prior settled saves, 4.50 ms with 500, 32.55 ms with 5,000. Single Node observations, not browser latency or retained heap. History grew by 100 in each case. Do not silently evict outstanding or terminal issue evidence. Further compaction requires explicit retention semantics (see integrity I11) and a representative long-session browser measurement.
- **P3:** private accumulation now appends. A counting iterator on the exact settlement statement, 499 ordered items, measured 124,251 previous-item visits before and zero after. Final item order was unchanged. This is **not** a wall-time or end-to-end linearity claim: subscriber progress snapshots still copy prefixes.
- **P4:** follow-up progress that changes presentation but not its persisted attention marker no longer rebuilds membership or rewrites the descriptor. The existing persistence test failed on the second write and now verifies one. A prior persistence failure still retries on a changed report. Other durable transitions still serialize the full descriptor; no shared cache or crash-window delay introduced.
- **P5 / P6:** lease fan-out and projection workload remain instrumentation questions, not established latency regressions. A browser cap does not bound durable operations per image. No service change, suppressed observation or new concurrency proposed; collect owning-store operations and projection lag separately if commissioning a local capacity trial.
- **P7:** explicit active-transfer stop addresses serial queue liveness (I10); no parallel buffers, hash worker or file-size timeout. Peak memory at realistic file sizes remains unmeasured. No measured campaign was authorized by the standing test policy.

## What one action costs

Counts below are code-path counts, **not** measured service requests per second. Assume warm discovery/session, one eligible changed target and no transient failure. Group preflight and post-write observation are additional, potentially shared reads. Unchanged operations can avoid a write. Server notification, indexing and upstream reads do not appear as separate browser requests.

| Command | Work between preflight and projection observation |
|---|---|
| Selected label add / exact remove | One owning edits read, then one POST/DELETE when applicable; selected-label command concurrency 8. A Form list clear can instead issue one sequential DELETE per distinct validated member. A mixed list edit can then add several members with one POST. [Label policy](../../../../src/lib/label-operation.ts#L19), [step loop](../../../../src/lib/grid-commands.ts#L305). |
| Scalar, location, people or keywords | One full image GET, one edits GET, one whole-map PUT. A queued predecessor witness can require up to three source reads total. Grouped non-label bulk operations may run five image executions; default three. [Source reads](../../../../src/lib/grid-commands.ts#L224), [group concurrency](../../../../src/stores/metadata-editor-store.ts#L327). |
| Rights | Owning edits GET, rights PUT, grouped projection checks, conditional derived POST, then normal operation observation. A nonpublisher category can still incur the derived request even when the server mapper returns no metadata change. [Transport](../../../../src/lib/grid-commands.ts#L252), [grouped readiness](../../../../src/lib/metadata-operation.ts#L8). |
| Manual lease | Full image GET for action, owning lease-set GET, one mutation if needed. Individual remove also reads the lease root. A syndication add or set replacement has **server** work proportional to the previous set, not one database action per HTTP request. [Command](../../../../src/lib/grid-commands.ts#L147), [clear/replace](../../../../../leases/app/controllers/MediaLeaseController.scala#L55). |
| Signed upload plus optional edits | One full-file hash, prepare, byte transfer, queued-status notification, status polling, then resource GET and scoped count. File available can start filename-if-empty and one label intent per preset. Direct upload has no client digest/prepare leg. [Transport](../../../../src/lib/upload-commands.ts#L94), [visibility](../../../../src/lib/upload-commands.ts#L180), [follow-up](../../../../src/main.tsx#L88). |

## Investigation ledger

| ID / priority | Cost and evidence | Cheapest useful check / decision |
|---|---|---|
| P1. Shared write capacity / rollout | `startIntervalMs` is zero. Local concurrency bounds **in-flight image commands**, not writes/sec across tabs or users. A 429 delays subsequent starts locally; it cannot coordinate other clients. The prior [GRID-019 record](../../bug-backlog.md#grid-019) reports fixed Edits capacity, not a new infrastructure reading. [Scheduler](../../../../src/lib/batch-execution.ts#L1). | Retain operator-scoped limits. Before general rollout obtain service-owner capacity/queue-lag evidence for the actual mix of operations. Do not load-test shared infrastructure or infer a safe fleet rate from local ACK timings. |
| P2. Long-session receipt retention / likely scaling cost | Every metadata save stays in `saves`. Updating one copies that map; dedup searches prior saves. Panel selectors scan history and reconcile terminal issues. Selected labels keep operations and receipts as well. The 10,000 cap is on **distinct images**, not saves to the same image. [Metadata submission](../../../../src/stores/metadata-editor-store.ts#L140), [updates](../../../../src/stores/metadata-editor-store.ts#L251), [panel history](../../../../src/components/MetadataEditing.tsx#L195), [label history](../../../../src/stores/label-editor-store.ts#L37). | Repeat successful edits to a small fixed set, then time one identical save and measure retained receipt/item counts at increasing history sizes; compare with a fresh tab. No retained-heap slope measured here. Preserve unresolved/visible receipts and latest field owners if compacting; do not evict freshness fences to save UI memory. |
| P3. Quadratic copying within one large action / code-confirmed | At each settled target `own.items = [...own.items, item]` recopies the accumulated prefix across groups. For one 10,000-target save this statement alone copies **49,995,000 previous item references**; for 499 targets, 124,251. These are counts, not JS heap usage or elapsed time. [Settlement loop](../../../../src/stores/metadata-editor-store.ts#L365). | First candidate for a low-risk improvement: accumulate privately per group and publish immutable snapshots only where a consumer can observe them. Compare a fixed mocked 100/1,000/10,000 action with identical outcome ordering and unchanged progress. No need for a backend benchmark to establish the copying. |
| P4. Full descriptor and membership rebuild per Upload transition / observed churn | `update` scans batches/attempts, then the subscriber derives all member IDs and calls [saveUploadBatch](../../../../src/lib/local-batch-storage.ts#L63), which validates and stringifies all attempts and scans other descriptors for the budget. [Subscriber](../../../../src/stores/upload-jobs-store.ts#L294). Follow-up-only changes can trigger work despite not being serialized as outcomes. | Existing native-storage measurements rule out a simple “setItem caused all jank” claim. Isolate preparation/validation time and count writes where the retained descriptor is byte-identical. Preserve synchronous crash-boundary writes when they change recoverable facts. |
| P5. Lease amplification / unmeasured family | Replacing an image with many leases enumerates prior records, reads and deletes individual records, sends removal notifications, then puts the new set and notifies. Syndication add also takes this route. This affects shared owner storage, event traffic and visibility lag even for a single browser PUT/POST. [Controller](../../../../../leases/app/controllers/MediaLeaseController.scala#L55), [store](../../../../../leases/app/lib/LeaseStore.scala#L27). | Local fixture with 0, 1 and several prior leases: count durable operations/events and compare ACK, owning read and indexed convergence. Do not extrapolate scalar Credit throughput to leases. Integrity of replacement is more important than parallelizing it. |
| P6. Observation and publication / bounded but not free | The connected observer can poll until the deadline, not just three times: the explicit attempt-count stop applies to the nonbatched path. Rights admission has its own three-attempt loop. Matching can scan receipt items per image; publication scans resident results and may copy the buffer. [Observer](../../../../src/lib/metadata-edit-execution.ts#L225), [rights](../../../../src/lib/metadata-operation.ts#L22), [publication](../../../../src/lib/image-publication.ts#L69). | For delayed rights/lease propagation count requests **and IDs per read** by phase; separate wait, parse, match and publication. Keep max 100 per dispatch group and 200 observation targets distinct from whole-action membership. Do not suppress readback to improve ACK-only numbers. |
| P7. Transfer memory and long-tail blocking / source risk | Signed upload materializes one entire `File` as an `ArrayBuffer` for SHA-1; queued files retain `File` references, not necessarily resident copies of all bytes. Transfer is serial. A large/slow first file delays every later submission; a stuck transfer is [I10](editing-integrity-ledger.md#i10-a-stalled-byte-transfer-can-hold-every-later-file-indefinitely). | Test one realistic large file followed by a small file under local transfer control. Record peak live memory, time to first usable image and all-available time. Do not substitute a hashing worker or add parallel full-file buffers without evidence. |

**Order of work:** retain the current concurrency settings; address correctness first. For client performance, investigate P2/P3 together with synthetic histories and measure the current lease path locally before proposing any service-speed change. Long-lived history, 10,000-target receipt copying and lease event fan-out are not answered by the existing 100/300/500-file comparisons. No performance change or new infrastructure is proposed as a prerequisite for ordinary prototype use.
