# Dev container config

This folder contains the configuration to work in a [dev container](https://containers.dev/);
an isolated, reproducible development environment that runs inside a container, typically Docker.

The configuration skeleton is generated by the Guardian's [devenv](https://github.com/guardian/devenv) config tool.

## Local corporate-CA overlay — quick orientation

This setup retains the standard Grid devcontainer plus a **personal certificate-trust
overlay** for corporate HTTPS inspection. It may be kept on a dedicated personal
branch or as uncommitted changes; it is not required by other contributors. It is not a fork
of the development environment: preserve upstream mise/PATH setup, Cucumber settings,
Playwright installation, Copilot plugin setup and shared-memory defaults.

The overlay has two trust boundaries:

1. **Host → devcontainer:** `prepare-host-ca.sh` exports one trusted public CA from
   macOS Keychain. `escapehatch.json` selects `Dockerfile`, which installs that CA
   into the standard base image **before Dev Container features run**. A post-create
   hook would be too late for feature-installation HTTPS downloads.
2. **Devcontainer → E2E image:** the E2E Docker build in `devenv.yaml` passes the CA
   as a BuildKit secret and enables its opt-in installation in the E2E Dockerfile.
   Nested images do not inherit the devcontainer's trust store.

Keep the local Dockerfile, export script, certificate ignore rule and README notes.
Combine upstream and local `escapehatch.json` keys; retain only the CA arguments on
upstream's E2E build command in `devenv.yaml`. **Regenerate configuration rather than
hand-merging generated lifecycle strings.** The pinned devenv generator supports
neither a first-class Dockerfile setting nor persistent personal build overrides;
the project escape hatch is deep-merged into both generated configurations.

Use the generator version below to reproduce the configuration. This also works
when the checkout's `.tool-versions` still selects an older generator. It does not
change the project's Java, Node or sbt pins.

```bash
mise exec github:guardian/devenv@20260930-111347 -- devenv generate
mise exec github:guardian/devenv@20260930-111347 -- devenv check
```

Generation overwrites manual changes to the ignored `user/devcontainer.json`,
including personal CPU/memory limits. Check generated output first, then reapply
any personal limits without removing the shared-memory setting. `devenv check`
subsequently reports that deliberate user-file difference.

When updating from main, preserve this overlay and regenerate from the combined
source configuration. If the overlay is uncommitted, temporarily preserve and
reapply it around the merge; copying upstream file content does not record merge
ancestry. Never stage exported certificates or personal generated configuration.

## Corporate HTTPS certificates

On macOS, `initializeCommand` runs `prepare-host-ca.sh` on the host before the
devcontainer build. It exports one selected CA from the System Keychain into
`.host-certs/root-ca.crt`. Git ignores this generated directory; no certificate
belongs in the repository. Only the public certificate is exported, never a
private key or the host's entire trust store.

The default certificate name is `Cisco Umbrella Root CA`, configured in the last
`initializeCommand` argument in `escapehatch.json`. To select another CA, either
change that default and regenerate the configuration, or set
`DEVCONTAINER_CA_NAME` in the environment used to launch VS Code. Restart VS Code
after changing that environment variable. The name must match exactly one
certificate in `/Library/Keychains/System.keychain`.

The preparation step stops if the selected certificate is missing, ambiguous,
invalid, expired, unsuitable as a TLS CA, or not trusted by macOS. It refreshes
the exported certificate on each initialization and only replaces a previous
export after validation succeeds. TLS verification remains enabled.

`Dockerfile` installs the exported CA into Ubuntu's trust store before
devcontainer features are installed. Installing it in `postCreateCommand` would
be too late for the Docker-in-Docker feature's Docker Compose download.

The supported `escapehatch.json` override selects this build and the host
preparation hook for both generated configurations. `image: null` clears the
generator's default image setting so the build does not reuse the upstream
image's local tag.

After configuration changes, run the versioned generation command above from the
repository root. Apply the changes using **Dev Containers: Rebuild Container** in VS Code.
If IT replaces the CA in Keychain, rebuild the container to pick it up.

Build-only commands such as `devcontainer build` and `docker build` do not run
the initialization hook. Before using them, run the preparation command from
the repository root and only continue if it succeeds:

```sh
bash .devcontainer/prepare-host-ca.sh "${DEVCONTAINER_CA_NAME:-Cisco Umbrella Root CA}"
```

Separate images built or run inside Docker-in-Docker do not inherit this trust
store automatically. The E2E image build passes the CA as a BuildKit secret and
sets `USE_HOST_CA=true`; its Dockerfile installs the CA before downloading mise.
The E2E Dockerfile-specific ignore file excludes `.devcontainer/.host-certs` from
its build context; the secret mount supplies the CA separately. The public CA is
intentionally installed in both resulting images, but no private key is exported.
The outer devcontainer build must retain the certificate in its own context for
its `COPY` instruction. Builds that do not set `USE_HOST_CA=true`, including CI,
keep their normal public CA trust configuration.

OS trust alone does not establish that every Java or Node client uses the same
certificate store. Verify the actual setup downloads and relevant clients after a
rebuild; do not disable TLS verification to work around failures.

## Contents

### `README.md`

Edit this file as you see fit.  It is created on the first run of `devenv init` but it won't be overwritten
by subsequent runs unless you delete it entirely.

### `devenv.yaml`

The source-of-truth configuration for this project's dev container. Edit this file
to add/remove modules or other settings, then run the versioned generation command
above to regenerate the shared and personal configuration files.

### `shared/devcontainer.json`

The main devcontainer configuration, committed to the repository and shared by all developers.
It is generated from `devenv.yaml`.

> [!IMPORTANT]
> Do not edit this file directly! Edit `devenv.yaml` or `escapehatch.json`, then regenerate using the versioned command above.

### `user/devcontainer.json`

A personal copy of the devcontainer config, **git-ignored** (see `.gitignore`).
This file is intended for your own overrides:
extra VS Code extensions or Intellij plugins, personal settings or tweaks that shouldn't affect other contributors.
Modify this file freely without worrying about polluting shared config.
> [!IMPORTANT]
> But be aware that `devenv generate` will overwrite it!
